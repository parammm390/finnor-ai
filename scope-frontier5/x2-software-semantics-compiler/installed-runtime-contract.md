# Installed X2 development boundary, before implementation

This is local staging/disposable engineering, not production activation,
protected admission, hostile-process confinement or Linux qualification.
Source and mounted-development-frontend evidence remain separately labelled.

## Failure model and independent acceptance

The current API has a real Next build/start owner. The worker and S6/S8
services currently launch TypeScript source. A copied checkout, source trace,
invalid-auth smoke, advertised build command or self-written success receipt
does not establish installed execution.

Use the already locked esbuild 0.25.12. Emit the actual worker registry,
physical queue driver, S6 server and S8 server, plus the existing consumer
entry for the owning production-build-mode probe. Keep third-party/native
packages external and installed locally; preserve canonical per-source
`import.meta` locations through the existing source-custody owner. Retained
source-loaded adapters remain explicit. Do not claim loader-free execution.

Build in a fresh task-owned installation outside the checkout. Include exact
canonical sources, locks, manifests, migration assets, native fs-ext and
locked dependencies. Use independent copy-on-write files, not mutable hard
links to the checkout. Reject dependency/source links escaping the installation
after relocating internal links. Do not import ambient `.env*`, private fixture
captures, peer overlays, undeclared donor paths or deployment configuration.
For a subsequent affected build, unchanged third-party files may share
byte-verified hard links with a stopped installation created by this task.
Never hard-link checkout/peer files or canonical source. Each new installation
still contains regular dependency files and its own relocated workspace
aliases, resolves without the seed path, and survives removal of the seed
directory. Record the seed inventory/digest and sharing strategy explicitly.
Run the real backend Next build with type validation enabled. Preserve source,
toolchain/options, input/metafile and output identities, duration and failures.
No build-cache deletion outside newly created task-owned output is authorized.

Before changing either S8 build-mode guard, exercise valid signed disposable
configuration in production Node mode. Require the actual consumer-policy and
authenticated application-command owners to return 403
`S8_PROTECTED_APPLICATION_DOMAIN_UNADMITTED`. Import, authentication, secrets,
source-custody or bootstrap failures do not count as reaching that guard.
Then admit only explicit staging + ordinary_disposable + disposable authority.
Keep signature/source/scope/currentness/loopback/false-authority requirements.
Production/missing environment, missing/wrong profile, protected authority,
non-loopback, invalid signature, altered source and wrong scope must remain
denied. An unconfigured consumer retains its existing optional behavior.

Production Node mode must omit `AUTH_DEV_BYPASS`, including the string `0`.
Synthetic local environment secrets require the existing explicit
`ALLOW_PLAINTEXT_ENV_SECRETS=1` warning, not an authentication bypass. The
independently signed disposable identity provider must validate real session
and refresh/logout semantics. No live credentials are required or adopted.

The decisive positive is actual authenticated built API -> canonical Work
and session -> durable queue -> emitted physical worker/registry -> admitted
application -> original independent readback -> four effects/actions/receipts
and canonical Work. Freeze the model before the fresh objective. Reuse the
unchanged separate portal evaluator and current native assertions.

Retain actual emitted process arguments and beginning/ending installation,
source, oracle and runtime inventories. Bind the installed asset identity to
the original runtime/source contract, without trusting an environment-supplied
digest or claiming that source filenames attest emitted bytes.

The installed identity reader uses the fixed canonical source-root path,
not an environment-supplied digest. Require a regular, owned, read-only,
no-follow/nonblocking manifest of at most 1 MiB and one to eight uniquely
named emitted assets, each at most 16 MiB and inside that canonical runtime.
All five current worker/registry/S6/S8/consumer role assets are required.
Verify actual asset bytes, Node/platform/architecture and the process's Node
binary before returning the identity. Changed/missing/unsafe installed bytes
must fence original use, not silently become a source-mode identity. A normal
source checkout without an installed-runtime directory preserves its existing
identity. The real installed positive and deliberate installed-byte mutation,
not a new private-predicate unit test, own these cases. Complete API/dependency
inventories are additionally checked by the launcher before and after the run.

The existing physical-loss/restart/original-observation variants own recovery.
Run their affected installed variants, preserving the same effect, obligation,
request, parent, reservation, allocation and original deadline. Include the
reviewed current-Work/input pending-effect invalidation case at this actual
physical boundary. No additional identity may resubmit a possible effect.
Retain UNKNOWN when original observation cannot resolve it.

The same installed stack must expose genuine maintained Work through a real
Deal/root and persisted Investigation. Browser lifecycle proof uses real
forms, real delayed responses, real auth/refresh/logout, offline/reconnect,
scope/principal switching and revocation. A development frontend must be
labelled as such; never disable CSP to pretend it is a production build.

Upgrade/no-op replay, ordinary non-BYPASSRLS roles, old/in-flight jobs and
standalone reconstruction remain mandatory. Reconstruct to a second fresh
root without checkout/donor resolution and execute a fresh installed episode.
Report billing, human work and simultaneous memory as UNKNOWN where unmetered.
No complete-cost gain, protected qualification or external gate is inferred.
