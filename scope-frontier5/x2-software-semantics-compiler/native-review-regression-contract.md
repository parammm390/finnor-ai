These cases extend the one actual native API/queue/worker/portal driver.
They do not add unit tests, test-only product entry points, fabricated receipts
or another success/authority/resource store. Existing API positive proofs
missed the boundaries below. Record pre-fix failures before repairing each
owner. Keep the original resources, deadline and independent oracle.

1. **Inclusive canonical S5 horizon.** A real canonical resource reports 2048
   units initially and zero at its terminal slot. An acquisition asking for
   2048 must be refused by S5, not a malformed resource or auth parser.
   Accepted ordinary resources and reservation envelopes have `periods + 1`
   entries. This also protects interoperability with canonical reservations.
2. **Current resource belief.** Change a pinned canonical belief dependency
   through its existing observation owner while the resource head remains
   unchanged. Forward spending/egress must be invalidated by S5. Original
   read-only reconciliation retains its separately bounded allowance.
3. **Compute deferral.** Hold the real `native:x2` slot with an actual canonical
   compute lease and deliver an accepted queued acquisition. It must remain
   resumable, retain original parent/resource/deadline and durable job deferral,
   and subsequently acquire the model after capacity returns. No effect may
   be sent during contention. The existing single worker positive misses this.
4. **Private request deletion.** In a scoped ordinary-role transaction, try to
   delete an actual `possible_egress=true` original request. The database must
   refuse it; always roll back. This tests inherited privileges and recovery
   custody, not just a table inventory.
5. **Fresh Work projection.** Feed the actual authenticated canonical fresh
   Work response into the maintained panel, including the frozen model,
   current owner-attested handoff and checked composition. Changed current
   grants/external authority epochs must not erase a valid completed Work.
   Stable identities and exact handoff links remain mandatory.
6. **UI nullable structure and rendering.** A real UI-only null-to-object draft
   change must remain independently observable. Then use the independent
   rendering revision with relocated action URLs and unchanged semantics.
   Learned semantic operation IDs must survive lawful private relocation;
   material semantic revisions must still invalidate the affected closure.
7. **S8 native versus application rights.** Actual model observations expose
   the external authority/grant epoch, while original Work/S6/S8 are attenuated
   by the native S1 rights revision. Do not conflate these two identities.
   The actual candidate, signed lifecycle, currentness, fresh composition and
   reconciliation must bind the right one at each existing owner.

The two final-egress/reconciliation identity regressions and their pre-code
repair contract are in `native-s8-integration-contract.md`.
All negative cases identify the exact owning guard and preserve failures.
None counts as business throughput or protected application qualification.
