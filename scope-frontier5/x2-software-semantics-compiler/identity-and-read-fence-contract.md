# Fresh identity dependencies and physical read fences

This supplements the frozen failure model before implementing these extensions.
It does not change the sixteen-field, eight-parameter or original-parent bounds.

An operation may require an application-created identity that does not exist
before its predecessor. The reusable model records an observed field dependency,
never a demonstration identity. Infer a dependency only when at least two
independently observed successful transitions on distinct authorized records bind
the parameter to the same typed pre-state field. The checker independently checks
those correlations against original evidence. Execution obtains the value from
fresh lawful readback. Search may carry a typed observation requirement, but a
placeholder is not an executable parameter, observed fact or completion.

Authority/account/credential/request-envelope metadata is not a business state
field. Application-created request dependencies are scoped identities. Nullable
object children distinguish observed absence from unavailable coverage; redundant
object-presence fields need not consume the finite state domain.

Every physical documentation, context, record, request or UI-entrypoint read must
pass the native current-actor/profile/claim/original-resource fence immediately
before its single request. Exact configured observation paths are not discovered
links. Other paths remain effect-bound, including nominal GET navigation.
Read attempts, response bytes, wall time and failures retain the original parent.
An aggregate observation bound cannot reset with a new session or worker.

Primary proof owner is the authenticated native API/queue/physical worker and
frozen independently administered portal, not an added post-code unit suite.
Credible regressions: literal dependency memorization, wrong account or record,
missing observation masquerading as null, multiple ambiguous current identities,
altered dependency correlation, direct unfenced discovery, stale read callbacks,
read amplification after restart, and unfenced deceptive links. Existing provider
readiness and predicate-only reference do not cover these contracts. The native
E2E uses no fixture-issued owner decisions and no test-only execution hooks.

Before repairing the wire encoding: keep canonical effect/request/parent UUIDs
and the S6 obligation reference unchanged. Encode the external obligation
correlation as `finnor_obligation_<canonical-content-digest>` and idempotency as
`finnor_<SHA256(canonical-obligation-reference, original-native-consumption-key)>`.
The exact owner validates both before retaining/dispatching the wire. This
opaque bounded encoding contains only letters, digits and underscores and
does not mint another effect, change the original parent or permit a replay.
Independent readback must echo the exact encoded tuple. No oracle or native
constraint is relaxed, and no portal-specific workflow mapping is added.
