# Native application owner contract

This contract precedes the additive native-owner implementation. The existing
failure model and frozen independent portal oracle remain the acceptance source.
This document does not supply an evaluation receipt or protected authority.

## Ownership and representation

- S4 selects a bounded checked application composition, not a numerical
  contingent intervention with relabelled doses.
- P1 invokes that S4 operation and the S6 continuation through typed owner
  operations. It does not choose business authority or mint a reservation.
- S5 uses its existing resource registry, proposals, reservation origins,
  reservations, consumptions, consumption states, charges and history.
  Application records are versioned variants, not a parallel budget ledger.
- S6 uses its existing obligation origins, BusinessEffect, DomainAction, native
  owner transport and native receipt/Work settlement. Immutable typed application
  requests and their attempt/observation evidence are retained separately from
  provider acknowledgements.
- Existing authenticated account/auth-profile and S1 Work/root rights supply
  scope. Credential material is resolved only inside trusted execution. An
  application principal is not the native accountable principal.
- S8 gains an additive `application-operation-v1` port in the existing journal.
  Its development admission grants no execution authority. Protected population,
  protected admission and production activation stay closed.

## Original parent

Create the S4 acquisition preparation and S5 reservation before discovery.
Bind the current Work input, tenant, native principal, root, rights revision,
profile/account, original deadline, source/runtime/lock cut and registered
resource demand. A semantic model may be reused only within those bindings or an
explicit checked fresh-binding handoff; reuse never replenishes the parent.

All discovery, structure reads, state reads, exploration, checking, planning,
physical requests, reconciliation, failed calls and maintenance consume that
reservation. Each consequential operation has one S5 consumption and one S6
obligation. Child deliveries and restarts share it. Exact reporting amounts are
not silently charged as cash expenditures.

Conservative request units are occupation, not provider billing. CPU/wall/bytes
meters have explicit coverage. Missing dollars, labor, provider usage or true
aggregate simultaneous peak remain UNKNOWN and cannot justify release.

## Exact wire and observer boundary

Every physical request is classified by its actual admitted binding, not its
method, label or learner-supplied effect flag. Exact observer/doc/context paths
have their own current scope/resource read fence. Every other request requires
the application S6 fence, including nominal navigation and mutating GET.

Before possible wire, independently recheck:

1. Current native actor, Work/root access, Work input and rights revision.
2. Current account/auth profile, application acting principal/role/grant.
3. Current model, independent check, operation, private binding and substrate.
4. Exact target, typed terms, quantity context, application and record revision.
5. Original reservation/consumption, remaining units and original deadline.
6. Actual durable job claim, generation, cancellation and execution position.
7. Stable obligation/effect/request/idempotency identities and exact wire digest.

Commit the sticky possible-egress marker and resource charge before wire.
Recheck current external context/version immediately before physical dispatch.
No request retry is hidden in an SDK. Generic BROWSER WRITE refusal remains.

Independent settlement requires lawful record/request readback, the exact
target/account/application/effect identity, version progression and typed
postconditions. A toast or HTTP acknowledgement is insufficient. A rejection is
independently denied only when current readback establishes unchanged state and
the admitted request surface establishes rejection.

## Recovery, drift and cancellation

After possible egress, recovery observes the original effect. It never creates
a new identity or repeats that mutation. If the original outcome is
indistinguishable, retain UNKNOWN, occupation and responsibility.

An accepted asynchronous request may retain pending state without completed
Work. Continue only after an independent observation establishes the successor.
At most one unresolved consequential operation occupies an original assignment.

Rendering relocation is a current lawful binding check, not semantic authority.
Material semantic or observation changes invalidate the dependent operation
closure and compositions. Historical models, observations, failures, charges
and effects remain. Unrelated independently current operations are not retired
by an unrelated rendering change.

Cancellation fences future wire/publication. It does not undo external effects,
clear UNKNOWN or release costs. Duplicate jobs and stale callbacks cannot
resurrect cancelled or prior-principal state.

## Pre-code decisive checks

The primary owner-boundary proof is the real authenticated API, canonical SQL,
non-root durable worker, independently administered application and maintained
Work chain. The fixture cannot supply native receipts or owner decisions.

Required regressions are: reset parent/deadline, incompatible concurrent
reservation, false guard/alternative/quantity/target/role, deceptive method,
revocation before wire, changed Work input, stale claim, response loss and
external SIGKILL, duplicate delivery, opaque readback, delayed completion,
rendering relocation, same-label semantic change, cancellation and prior-user
response resurrection. Each must reach its named boundary after an authorized
positive has demonstrated that boundary.

The existing finite predicate reference is not proof of the new transition,
composition, native accounting, transport or S8 paths. No post-code unit suite
will be substituted for the frozen external oracle and native E2E proof.
