# Independent X2 acceptance specification, before critical code

The learner is an untrusted producer. The checker uses original permitted observations and current independent owner state, never learner-selected expected transitions or locator code. The external application and business assignment oracle are independent of finite-model proof.

## Failure families

1. Literal demonstration replay, embedded record/account/private fact, application-specific engineer mapping, or per-task improvised routes instead of consuming the frozen operation algebra.
2. Missing/ambiguous precondition, false-valid or false-invalid guard, vacuous empty supported domain, incorrect successor implication, unavailable observation treated as true, unbounded search/loop or silent sample truncation.
3. Wrong application/account/role/principal/record/units/currency/date/basis, lossy financial coercion, incorrect null meaning, forged evidence/checker/runtime/model revisions or locator substituted for business semantics.
4. Button/method/network deception, unauthorized navigation/autosave/preparation, grant revoked during discovery/planning/physical commitment, prompt injection or cross-tenant disclosure.
5. Toast/acknowledgement treated as durable completion, delayed observation, absent postcondition identity/coverage, solver result treated as external behavior, stale callback/readback.
6. Response loss or SIGKILL after possibly accepted effect followed by new identity/replay, duplicate jobs or concurrent Works causing double reservation/egress, cancellation falsely undoing effects or releasing UNKNOWN exposure.
7. Rendering drift assumed semantic safety, unchanged label hiding changed confirmation, overly broad invalidation, failed prediction erased, stale model/composition replay, unauthorized relearning.
8. Descendant acquisition/checker/browser/solver/recovery resetting parent deadline/budget; unavailable provider usage recorded as zero; missing billing/labor/aggregate-memory coverage presented as known.
9. Candidate self-admission, evaluator/promoter same principal with different keys, changed sealed oracle/custody, protected generic BROWSER enabled by configuration, admission mistaken for authority.
10. API/source proof substituting for physical worker, canonical native receipt/effect/Work, installed bytes or mounted user behavior; auth bypass mistaken for fresh sign-in; delayed response resurrecting prior private data.
11. Broken old/in-flight job, schema/migration/order/restart, generated client/form/manifest, unsupported runtime platform or reconstruction depending on hidden peer files.
12. Refusal used as business throughput, easy-case selection, failed/unsupported/time-out denominator removal, incumbent WRITE refusal used for infinite gain, incomplete costs or unqualified B_V used for 100×/financial credit.

## Independent acceptance

- Validate complete original evidence identity, scope, freshness and retained bytes before checking candidate claims.
- State/parameter predicates are total only in their declared typed finite domain. Unknown and inaccessible values are not Boolean false or a satisfied guard.
- A learned operation needs independently expressible pre/postconditions and evidence coverage. Unobserved generalization remains uncertainty, not complete transition identification.
- Check parameter/target bindings and units exactly. Quantity arithmetic/serialization uses exact strings/integers; display rounding cannot reach execution.
- A checked composition preserves predecessor/successor state, read/write interference, asynchronous observations, roles/grants, all original resources/deadlines and known/UNKNOWN obligations. A missing implication requires lawful observation or an explicit gap.
- Before every physical effect, current canonical authority, target/account, owner/application/model revisions, exact request/effect identity, parent reservation and observation contract must match. The request passes S6 regardless of model labels.
- Independent observer uses an authorized surface and exact identity/field/version/effect predicates. Toast, producer prose and response acknowledgement cannot settle an effect.
- Possible egress is durably recorded before wire. Recovery uses original identity and admissible readback only. If missing versus duplicate cannot be distinguished, UNKNOWN remains.
- Candidate mutations must reach their intended checker. Track false-valid and false-invalid separately. Positive authorized fresh reuse must also pass, excluding an all-refusing implementation.
- Finite proof checks only encoded assumptions/grammar/bounds and reports accepted proof, counterexample, timeout/UNKNOWN or unsupported separately. Independently replay accepted candidates and counterexamples through a reference and actual consumer.
- Every E2E retains exact inputs/source/runtime/schema/oracle, intermediate/external state, physical fault timing, actual API/queue/SQL/process/mounted steps, effect/grant/deadline/resource lineage, raw failure/cost gaps and a secure rerun.

## Test-authoring gate

For each new/changed verification case record observable contract, credible regression, missing stronger coverage and real owning entry/egress boundary. No post-code unit tests, copied expectations, source-grep acceptance, receipt-supplying mocks or earlier unrelated refusal as the negative oracle. Application-level/reference proofs own the contract.
