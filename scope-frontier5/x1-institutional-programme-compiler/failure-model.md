Written before critical compiler/checker code. This is an independently specified engineering failure model, not proof of correctness or protected oracle custody. The accepted native plan, original goal and profile remain binding.

## Adverse cases frozen before implementation

Checker challenge set C contains separate correctly scoped candidates for wrong entity, wrong currency/unit/magnitude, impossible chronology, wrong deadline, unsupported normative rule, suppressed contradiction, omitted obligation, stale revision, unauthorized operation, foreign tenant/source/principal and forged check. Every record states which guard must be reached; earlier unrelated refusal is not success.

Physical D/E faults use the actual worker and durable SQL/action boundaries. Test fixtures may coordinate locks/process death externally; no test-only production bypass. Original accepted children, grants, deadlines, costs and UNKNOWN effects survive.

### Registered owner case B-ledger-correction

Before adding this E2E case, freeze a correction from USD 20.00 to USD 25.00 for
the same Deal, period, unit, accounting basis and ledger record. The standing
Request-creation rule depends only on its separate work-tracking trigger and
mandate. Credible regressions are a stale positive read, failure to queue the
actual P7 update, replacing the original resource parent/deadline, failing to
publish the independently checked correction, invalidating the unrelated duty,
duplicating its already observed Request/effect, or rewriting its prior proof.

Use actual Core version append and a superseding ordinary source-grant version;
keep its purpose, principal, source class, validity interval and all other source
handles. Observe the registered physical update/compiler/native workers and
canonical ending rows. No direct call to the update handler or candidate edit
is permitted. This case covers the ledger correction and unaffected continuation
subset of B; the complete PRD fixture and remaining B variants stay required.

### Registered owner case A-eight-class-original-corpus

Before adding this E2E case, freeze twelve source instances across eight classes
and twelve direct original-byte protocols. CRM identifiers have conflicting
names; document/mail/calendar/approval records corroborate scoped identifiers
without supplying approval authority. One work-tracking trigger requires one
native Request. Two fully contextualized quantities retain their stated meanings.
DOCX/XLSX/PDF are real binary originals; pagination, delimited tables, RFC822,
iCalendar, XML and HTML use their actual framing and complete object populations.

Credible regressions include producer/checker disagreement on native fields,
forgotten metadata aliases, calendar entities misclassified as scheduled claims,
silently omitted format records, accepting a source header as authority, losing
byte identity or faking eight classes with JSON labels. Require ten independently
specified mappings, two quantities, one original duty/effect and native Work
completion. This is an engineering corpus; it supplies no protected unseen
population, hosted connector, sensitive-access or complete fourteen-kind proof.

### Registered owner case A-fourteen-canonical-kinds

Before adding this case, freeze the fourteen profile kinds as the expected
mapping population. Create each prerequisite through its actual Core/Memory/PE
owner; sensitive person input requires the active employee's source-scoped
identity evidence and subject-issued consent. Two fund identities share a name
without merging. Requests, Findings and Decisions are existing records; a draft
Decision assertion grants no approval. One separate trigger still requires one
new native Request. No other commitment is inferred from entity existence.

Credible regressions include wrong canonical kind, guessed identity from a name,
lost Core evidence attachment, unsupported native world roots, revoked sensitive
consent, changed owner version or treating a relationship record as a Deal.
Independent SQL must verify each immutable admission's target, evidence entity
reference and native/Memory attachment plus the same bounded creation proof.
This is a development case; it does not establish protected domain qualification.

### Registered owner case D-compiler-before-publication-death

Freeze the real first compiler delivery blocked at immutable mapping admission
by an external SQL table lock. Observe its actual SQL lock wait and claimed job,
then SIGKILL that owned OS process. No product checkpoint or fake handler is
used. The native queue's existing expired-lease recovery must quarantine the
potentially consequential delivery; readback must retain UNKNOWN, never imply
failure, completion or permission to replay an effect.

Use the supported five-second test lease from the first worker launch, while
retaining all original episode and host limits. Restart only the physical worker
after observed death. Authenticated resume keeps the same compiler request,
grants, Work input, original episode/reservation/deadline and monotone counters.
Require one actual eventual Request/effect and completed native Work. Credible
regressions are permanent RUNNING after death, blind queue replay, a fresh parent
or action identity, lost cost history or a stale claim publishing afterward.
This case covers pre-publication compiler death; lost effect acknowledgement and
other registered interruption points remain separate required cases.

### Installed baseline and immutable parent bindings

The full output currently carries an avoidable unknown baseline and empty parent
list even for a successor. Before repair, freeze these failure conditions: a
source/runtime/lock/schema/profile substitution must not receive a known B_live
binding; an original grants/resource envelope must not be presented as qualified
B_V; a successor must reference its exact immutable parent artifact, including a
digest verified from stored bytes. Record unavailable Git/build or preparation
qualification as explicit gaps, never invent commit or completed qualification.
Persist the actual baseline preimage with the immutable owner artifact, and verify
it at authenticated readback. Original-source and signed qualification custody
remain separate. Reuse the real material-correction E2E for parent lineage.

### Registered owner case E-original-shared-parent-contention

Keep the completed standing Work's original 520 compute/900 human reservation
active. Submit a second actual Work with the same permitted Deal root and current
ordinary source/mandate authority, using the same finite resource pool. Its
compiler must refuse at S5 shared capacity without another reservation, effect
or source population shortcut. Cancel that refused second compiler through the
authenticated API. The first Work's reservation/envelopes, resource revisions,
completion proof and one observed Request remain identical. No resource is
refilled or released merely to make the second task succeed. This covers real
S5 contention and cancellation before exposure, not every concurrency variant.

### Registered owner case F-mixed-unsupported-rule

The current mandate has one supported evidence-Request rule and a second rule
whose approvalCondition meaning is unsupported. Both have explicit original
principal, deadline, operation and observer. The unsupported field is not an
approval, and must not be silently dropped. One actual native Request from the
independent supported rule is allowed; the other duty retains a precise missing
interpretation under its original identity/rule digest/deadline. The programme
remains PARTIAL and Work cannot claim full completion. Preserve all costs and
the same parent. No human reconstruction or fallback flag receives credit.

The independent oracle contract defines expectations and preservation. Boundary bugs need a pre-fix failing regression at their owning boundary. No post-code unit tests. Source changes following a failed proof retain the original run and rerun only affected proof plus necessary regressions.
