# Native source corpus, registered before implementation

The ten class/protocol identities and outcomes in `native-expectations.json` are independent expectations. Input records use class-native vocabulary and content rather than `kind`, `entityType`, `registrationId`, `factKey`, `triggerKind`, `X-Institution-*` or canonical target IDs. CRM opportunities and counterparties, ledger journal amounts, DMS narrative, RFC822 body, iCalendar meeting, task evidence request, XML decision, lender HTML facility, HR employee and expense receipt differ in structure and meaning. A checker reading original bytes must independently derive its denominator. An email asking for an exception is never a mandate or approval. Date ambiguity, missing units, names without scoped identifiers and missing cross-references stay unresolved. No source assertion grants access or sensitive consent.

The checker-001 regressions in `review-cases.mts` are owner-boundary cases, not post-code unit tests. Observable contract: distinct source/record and trigger/rule tuples, typed quantity context, actual deal count and semantic comparison reject/accept at their registered guard. Credible regression: the reviewed composite separators, truthiness/type coercion, claimed counters and JSON property ordering. The earlier flat control corpus has none of these variants. These cases target the independent checker itself, not an injected mock. The stronger stale-original-with-refreshed-label case additionally requires a previously pinned original-byte/source revision; metadata supplied in the same mutable input is insufficient evidence and must not be accepted as a current owner read.

This is development evidence, not protected custody or canonical admission. Existing flat protocol cases remain controls, not evidence of native reconstruction.

The next owner must supply `current.sourceDigests` from its own immutable source reread. If absent, metadata revisions alone cannot reject an old original supplied with a new label. `checkInstitutionInSeparateProcess` currently executes the source-script entry with the installed development `tsx` dependency; an installed checker entry and owner-side code/profile pin authority are not yet verified. The owner must not accept a caller-supplied `sourceDigests` map as trusted currentness.
