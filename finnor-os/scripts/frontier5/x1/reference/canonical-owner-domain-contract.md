# Canonical owner domain adapter — pre-code boundary contract

The frozen profile includes funds, vehicles, deals, investment cases,
counterparties, people, documents, metrics, facilities, relationships, Work,
Requests, Findings and Decisions. Add readers and assertion attachment through
their existing owners. Do not create a parallel institution truth directory.

PE records bind tenant, institution import namespace, stable registration,
actual entity type/version and current lifecycle. Core counterparties bind an
explicit organization key, documents bind current owner provenance/versions,
Work binds its actual ID and principal, and personnel bind the current
source-scoped identity-owner binding plus active employee and actual consent.
Names, narrative similarity, accounting balance and UUID-shaped text are not
identity proof. Same identifier in distinct kinds/contexts is not one entity.

Before publication reread and lock the same owner preimage; fail a wrong tenant,
person, source, registration, kind, version, archived/superseded entity, revoked
identity/consent or changed Work. Keep all unmatched alternatives explicit.
Only the existing fund/vehicle creators may create their supported new records;
missing legal/financial/role evidence cannot be invented to mint other entities.

Core assertions use Memory evidence entity refs and Work links. PE assertions
use native PE evidence attachment with a genuine supported world root. A source
assertion does not change canonical truth, approval or effect authority. Receipt
readback verifies the actual evidence version/attachment, including Core refs.

Independent source/checker expectations must preserve cross-type and
source-scoped collisions and complete material mapping/obligation denominators.
Use the named A/B/C/G real-owner scenarios when live capacity is available.
No new post-code unit suite or self-generated protected mapping ledger.
