# A-owner-source-and-admission, independent expected boundaries (pre-code)

The owning boundary is a tenant transaction with authenticated Work/principal,
not candidate metadata. An active, versioned source grant names a Core original
DocumentVersion or an installed read-only adapter/object. A current grant binds
the principal, source class, purpose, expiry and original digest. Personnel and
expenses additionally require every affected subject's active consent for that
same purpose and class, at both retention and admission. An absent subject,
expired consent, revoked grant, changed original version, foreign Work or
caller-supplied `authorizedPrincipalIds`/`current` cannot reach admission.
Independent authorized sources continue when one source has an explicit gap.

For a CRM row `opportunity-7` with scoped `FIRM-100`, candidate Deal
`pe_deal:<id>@v1` is usable only if the existing Deal has that exact scoped
source identity. A new Deal needs an already established target organization,
current lead employee, signed-LOI occurrence and target-closing date. A name,
CRM stage or email cannot supply missing prerequisites. Preserve the unresolved
Deal while an independent, exact fund/vehicle or Core organization source may
create its canonical row and Work/evidence relation. Independent original bytes
and the owner identity witness must be checked before publishing a mapping.

Source Truth observation, EvidenceVersion, canonical attachment, Work link and
the admission receipt commit in one transaction. If an attachment fails,
Source Truth cannot appear mapped to a fully admitted X1 result. Duplicate
delivery with identical original and candidate identity returns the existing
receipt, not another canonical entity or claim; changed digest/version refuses
the replay. A conflicting provider sequence, revoked right or changed canonical
version must fail before publication, never silently settle a contradiction.
Readback must compare the canonical row, evidence version and Source Truth link.

The separate checker receives the original immutable bytes, mandate and
canonical snapshot from owner reads. A process/image pin change, candidate
change or source byte change refuses. Physical process separation is
development-only, not protected custody. These cases are intended for the
authenticated A/C owner driver once the registered live floor permits it.

Installed Microsoft Graph mail is a narrow real adapter: an active source
scope's exact mailbox and an immutable message ID bind a read-only
`/users/{mailbox}/messages/{id}/$value` MIME request through its credential
owner. The exact returned RFC822 bytes, not normalized fields or a fabricated
wrapper, are retained in a Core DocumentVersion and a source acquisition
receipt. A disabled scope, wrong integration, missing permission, wrong
provider, oversized bytes, incomplete object, provider revision mismatch,
expired grant or unsupported adapter family fails closed; no generic URL fetch.
Reacquisition under a different digest is a conflict, never a rewrite.
