# X1 recovery and owner-currentness boundaries

Engineering evidence requires the installed authenticated API, physical queue,
claimed worker and canonical owner reads. Source inspection and the offline
development driver do not satisfy these boundaries. Do not start the stack below
the frozen free-disk floor. Retain original failures, identities and cost history.

1. Admit a mixed established Deal and established Person/Metric request. Publish
   only original-source assertions through Memory/Source Truth and supported PE
   evidence roots. Re-read the actual owner version and evidence attachment. An
   unrelated unsupported observation stays a gap and does not abort that duty.
2. Pause after admission. Change the exact subject version or its source-scoped
   identity binding while grants, mandate and authority revisions remain fixed.
   Read, dispatch and the mutation transaction must withdraw stale readiness.
   Revocation, archival, supersession and a remap to a different active person
   are separate failure variants. A current old binding is insufficient if a
   second current binding makes the same source identifier ambiguous.
   For a canonical Document, change a current version head without changing
   document provenance; the owner cut must detect it. Head writers and a locked
   effect reader serialize through the actual Document row.
3. Accept the native action, SIGKILL the claimed continuation after RUNNING,
   then reclaim the same physical job three times. Preserve the original P1
   episode, saved head, stable obligation and DomainAction ID; do not re-lower
   q.proposed or spend a fresh preparation attempt. Lost acknowledgement must
   reconcile the same accepted action. Old claim publication must be refused.
4. Keep the action pending beyond observation poll 60, then verify it before
   the original deadline. Automatic observation must resume within the frozen
   original wall/resource envelope. A deadline expiration records an explicit
   bounded stop; it must not leave an unscheduled WAITING request or invent
   completion. Cancellation or generation change fences every later poll.
5. Read the immutable InstitutionProgram envelope. Its exact Work revision is
   the actual work_inputs ID and its owner-row digest, independently re-read
   from the database. The compiler revision ordinal is a different field.
6. Observe creation duty A while B is pending. Legitimately acknowledge A's
   Request or start its Workstream through that canonical owner, then complete
   B. Preserve A's sealed timely creation observation under its unchanged
   stable identity, derivation and frozen action intent. A creation obligation
   does not require the entity to stay in its initial lifecycle state forever.
   Explicit invalidation still withdraws current readiness and retains history.

Every run must export authenticated input handles, setup owner receipts,
physical job/delivery/claim IDs, interruption points, canonical observations,
status transitions, costs, failed predicates and a finite rerun command. Current
status of these live cases: NOT RUN for the repaired cut.
