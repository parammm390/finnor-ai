# Z1 native SharedWorkProgram engineering

This is ordinary disposable engineering, not protected admission, production
activation, source truth, business completion or a qualified financial speedup.
Source implementation, compiled installation and authenticated native execution
have separate evidence. No driver creates a database, tenant, Auth project, Work,
resource, source, grant, listener or effect.

## Canonical path and shared ownership

The six strict operations in `private-equity/.../api.ts` delegate from the existing
authenticated `/api/company-brain/:operation` route. They reserve each existing
original Work's immutable S5 budget, submit reference-only original declarations,
read bounded history, admit a separately checked ordinary derivation, project an
original result and cancel without erasing costs or S6 responsibility.

The actual queue handlers are `run_shared_work_program_v1` and
`consume_shared_work_projection_v1`. They require canonical durable claims,
fixed INTERACTIVE classification, the serial `provider:z1-shared-work-native`
policy, current original cuts and real S5 parents. The first executes the bounded
Node producer and separate direct-original Python checker. Ordinary S8 admission
enables transactional consumption by the actual original S3 or S4 owner. S4
records/finalizes a canonical decision but never dispatches an effect. Outstanding
S6 responsibility produces an explicit WAIT, not disappearance or Work completion.

`integration-request.py` emits full shared-file postimages, exact preimage/postimage
SHA-256s and a unified patch. It never applies anything in a worktree. The API
delegate, two registry entries, compute contracts, complete S5 snapshot integration,
existing WORLD Work mount, proxy body bound, OpenAPI/manifest generators and build
tracing must be integrated together. The coordinator owns collisions and acceptance.

`shared-schema.sql` is an unexecuted proposal. The coordinator must assign its exact
complete migration filename and regenerate the ordinary migration bundle. Do not
pick an ordinal here, run SQL, change privileges or launch a stack. If an exact
coordinator-assigned name is delivered later, request emission accepts
`--coordinator-assigned-migration`; this still emits a request, not an application.

## Reconstructible installation, no native authority

Use Node 22, the configured npm and Python 3.12. Bound full-graph checks to 4096
MiB under the shared heavy lock; other commands use 1536 MiB. Freeze the own native
source in a local ordinary commit first.

```sh
cd /absolute/source &&
flock -x /home/factory-user/repos/finnor-z-shared-heavy.lock \
  python3 /absolute/source/finnor-os/scripts/project-z/z1/reconstruct-native.py \
  --source /absolute/source --output /absolute/new-evidence --archive-installed
```

The command archives declared tracked source, applies requested shared bytes only
inside a new validation copy, installs both lockfiles with a new home/cache,
generates the existing contracts/stamps, runs full backend/frontend types and
catalogue checks, and builds the API and a separate `.next-z1-install` frontend.
It executes public exact/process/recovery E2Es, not database tests. It records
every actual exit, log hash, source/patch identity, dependency/native asset and
build ID. It removes its temporary copy after retaining the package.

`package.json` in the evidence directory identifies the source archive, exact
integration request and installed artifacts. Replay requires those delivered bytes,
not a local Git repository or borrowed modules:

```sh
flock -x /home/factory-user/repos/finnor-z-shared-heavy.lock \
  python3 /absolute/delivered-source/finnor-os/scripts/project-z/z1/reconstruct-native.py \
  --replay /absolute/package/package.json --output /absolute/new-replay
```

`stamp-installed.mjs` binds all declared owner source files and the requested patch,
not just the kernel. New workers rehash the complete cut; subsequent probes stat
and rehash changed files. This is source consistency under the trusted filesystem,
not an attestation of OS, compiler, DB administrator or dependency correctness.

The optional `requirements-sql.lock` pins the offline parser wheel. `parse-sql.py`
checks SQL/PLpgSQL grammar with the parser's recorded PostgreSQL version. Catalog
composite local variables become `record` only for grammar parsing. No catalog,
role, trigger, RLS or transactional behavior is thereby verified.

## Limits and custody

The kernel retains the locked 2–1000 Work / 4096 original-node / 100000 source-row /
1000000 newly derived-row / 512-bit rational / 128 MiB bounded request domain.
Native S1 append uses the existing smaller per-version storage boundary; this
does not certify a 128 MiB S1 write or a full native boundary episode.
Admission also respects the existing S5 limit of 256 outstanding commitments.
Resource exhaustion returns INCOMPLETE; no 1000-Work native capacity qualification
or increase to canonical portfolio limits is claimed.

Complete exited-child `wait4` CPU/RSS is observed, with a separate pre-FINISH
supervisor meter. Parent intervals, logical allocations, JSON write occupation and
conservative outstanding CPU holds are retained. Supervisor exit tails, true
aggregate memory, S5/S7/WAL/index/physical storage, provider/cloud/human and money
remain incomplete/UNKNOWN, never zero. No complete financial comparison follows.
A producer PID without its atomic checkpoint is also unresolved logical exposure.
The next attempt commits INCOMPLETE and cannot compute again from that apparent
headroom. A missing receipt is not zero use, and cancellation does not reconcile it.

The ordinary application and DB credentials/filesystem are trusted implementation
boundaries. A principal with direct application DB credentials can write ordinary
native records; these records are not protected custody. SQL runtime enforcement,
cross-principal RLS and actual native contention still require the authorized
disposable installed episode. Never turn source checks or a grammar pass into
these execution or qualification claims.
