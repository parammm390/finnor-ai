# Z2 native replay, installed reconstruction and public obligations

These scripts are engineering equipment, not authority to create a target.
They do not initialize a DB, tenant, Auth user, source fixture or reservation.
They do not migrate, grant permissions, start listeners or dispatch effects.
There is currently no authorized native target. Missing authority is NOT_RUN,
not a fabricated positive and not an excuse for an unfinished local build.

## Frozen source and separately installed build

Run `emit-wiring-request.py --repo /absolute/own/repo --evidence-dir
/absolute/new/packet` and `prepare-replay.py --repo /absolute/own/repo
--patch-dir /absolute/new/packet --output /absolute/new/reconstruction`.
The coordinator patch is checked and applied only in the new reconstruction.
Shared source and generated catalogues remain coordinator-owned.

`install-owner.py --repo /absolute/own/repo --source-tree
/absolute/new/reconstruction/tree --evidence-dir /absolute/new/install
--node /absolute/pinned/node22` copies that source, runs both locked `npm ci`
installations, rebuilds and loads native flock, generates/checks catalogues,
stamps existing X/Y source cuts, checks both full TypeScript graphs and lint,
bundles real API/worker/UI roots, executes separately emitted process copies,
and runs the existing actual API and frontend builds. It serializes heavy
work under the shared lock with a 4096 MiB engineering heap. It never starts
services. Inputs, generated changes, final sources, outputs, logs, actual
exits and both BUILD_ID values are retained. Only the exact Next distDir
type-import rewrite is allowed for the root next-env file.
The installed lock-bound Playwright CLI downloads only its default headless
Chromium variant into that installed target, not a shared cache. The public
Playwright launch selects it, and its actual PID/executable/hash is checked
inside that target before interaction. No unused full Chromium variant is
required. A literal local document is clicked
and rendered by that exact executable over a pipe, with no server, DB,
Auth or external page. Its input, observation, screenshot, binary/process
identity and actual physical exit are retained. This is packaging evidence
only. Missing public downloads or Linux libraries fail the engineering
check, without sudo, OS package installation or TLS-verification changes.
An optional `--temporary-cache-parent /dev/shm` places only this run's npm
download cache, Node headers and temporary files in a new private temporary
directory. Dependencies, browser binaries and all runtime assets still live
inside the new pack. Npm logs and an actual cleanup receipt are retained;
only that fresh temporary directory is removed, including on failures.
Older installed packs and failure evidence are never pruned.

The installation receipt distinguishes a successful build from actual
authenticated installed owner execution, which remains NOT_RUN. The emitted
process harness is not an API server, database, mounted Work or worker claim.
No Docker-image execution is inferred from an API build or a source COPY.
The native binaries and Next trace closure have separate exact inventories.
A complete browser asset inventory and declared Node/Chromium system-library
inventory are checked too. System libraries are explicit OS toolchain inputs,
not undeclared browser-cache fallback.
A traced directory must have a nonempty, completely hashed file inventory;
it is not a waived trace. The replay verifies its exact count and digest,
refuses symlinks/undeclared files inside it, and checks source/output
realpaths remain inside the installed target. Root Markdown selection is
limited to explicit instruction/README/notice names, never credential metadata.
Historical owner-proof documents are excluded. Only canonical generated
capability coverage is needed from that documentation tree. The installed
build blocks parent Git discovery with a process-local ceiling and retains
the expected `rev-parse` exit 128, without changing Git settings or hooks.
The exact coordinator request also adapts the canonical coverage auditor:
ordinary builds retain its original proof-file/Git behavior; the isolated
build uses a fixed hash-pinned `.z2-source-build.json`. That input carries
the actual source-base commit and metadata-only original coverage index.
The generated index visibly says `DECLARED_BASELINE_INDEX_NOT_REOBSERVED`.
It is not fresh historical-proof observation or current native owner proof.
Its deliberately wrong-hash refusal is exercised through the real auditor.

`obligation-replay.py --repo /absolute/frozen/tree --evidence-dir
/absolute/new/obligations` separately names all eight obligations per family:

complete impossible owner target, lawful versus unauthorized local plans,
original source/model/operator binding changes, finite resource/arithmetic/
deadline refusal, and durable native interruption/duplicate handling.
It drives real producer/checker subprocesses and an independent direct
original-history oracle. It retains all actual exits and original inputs.
Family 30 has no stable positive by definition, so its two positive cells
are explicitly NOT_APPLICABLE and excluded from the positive denominator.

and prerequisites, not a process restart masquerading as physical recovery.
Source/model binding refusals do not prove actual rights or terms mutation
before native owner use. Process resource refusal does not prove the actual
parent reservation recovered. Those native obligations remain separate.

## Target contract and offline validation

`native-replay-target.schema.json` describes the operator-supplied target.
`native-replay-target.template.json` is deliberately invalid and expired.
It names no invented tenant, principal, Work or process. Fill every required
field from the actual authorized target; changing booleans alone is not
authorization. The installed CLI checks that this unfilled template refuses
before DB/Auth access.
`native-replay.mjs --validate-target --target /absolute/target.json
--evidence-dir /absolute/new/offline-proof` validates the declared target
structure and exact installed source/build/driver manifests without DB,
Auth, browser or process mutation. The real native owner remains the strict
validator of SubmitSchema and every source, terms and observation contract.
Offline validation is not live ownership validation or native execution.

`offline-target-fixture.mjs --whole-owner /absolute/whole-owner-install
--output /absolute/new/target.json` emits a schema-valid offline fixture
target whose source-final map, receipt hash and receipt digests are taken
verbatim from a real passed installation, and whose actors, cases,
reservations, ports, issuers and process identities are inert fixture bytes.
It exists to exercise the positive offline binding path end to end. It emits
`validationOnly=true` and five false execution grants, never invented
authority. The closed schema permits exactly one of an inert fixture and
an operator target; removing the marker or enabling a fixture grant fails.
The driver refuses marked fixtures in execution mode with
`Z2_OFFLINE_FIXTURE_NOT_EXECUTABLE` before operational lookups.
`--validate-target` never reaches an execution branch, starts nothing and
touches no DB, Auth, Work or port. A pass records
`VALIDATED_TARGET_BYTES_NOT_EXECUTED` with the exact external blockers.
The first such run against whole-owner-05 validated the full binding chain
(2890 source files, build receipt, output manifest, trace closure and
traced directories, native and browser asset inventories, system libraries,
node identity) and is retained at
`scope-z/phase-evidence/z2/native-offline-validation-02` with its failure
model in `native-offline-fixture-contract-01.md`; the retained `-01` run
records a real fixture defect caught by the schema gate. Live authority,
process identity and native execution remain unvalidated and NOT_RUN.
That historical run predates the hard fixture isolation. The current
`offline-replay-e2e.py --repo /absolute/installed/pack --whole-owner
/absolute/whole-owner-install --evidence-dir /absolute/new/cli-proof
--node /absolute/pinned/node22` exercises generation, positive full binding,
fixture schema/execution refusals, realpath output containment and exclusive
creation through the actual installed CLIs. It retains all inputs/exits.
The refusal case uses a nonexistent source canary and no credentials; it
does not attempt a native owner operation.

The target must refer to:

- An already authorized, exclusive disposable database. Use an existing
  restricted non-superuser/non-bypass role, never the `postgres` database.
  Its existing privileges must already include the canonical `finnor_worker`
  queue authority, available without SET ROLE. An application-only role
  cannot drive the worker's global queue. This is checked, not granted.
  The replay does not grant this role anything. SQL observations are SELECT
  only, with the original tenant/principal transaction context. A scoped
  worker role can inspect the queue, but an empty queue does not prove
  absence of another future writer. Exclusive DB ownership still needs
  real independent authority.
- A matching real frontend/API Auth issuer and two through four distinct
  real active owner-role participants. Credentials are environment values
  only. No tokens, passwords or emails go in the target, commands or proof.
- A successful current `whole-owner-install.v1` receipt, its actual installed
  root, full final source inventory and output inventory, exact build IDs,
  matching Node binary, and owned frontend/API PIDs, start ticks and command
  hashes. The driver checks ownership of the actual listening socket too.
  The installed root, backend and API directories must have no `.env*`
  files, because the canonical worker imports dotenv.
- Existing original Works with their actual executable input, admitted
  same-Work Y1 theory, fixed meanings, current typed canonical source/model
  claims and exact original S5 reservation/revision. Positive Works must
  not already have Y3 requests. Each case has a distinct existing Work.
- At least four original native cases covering CLAIM, CHECKPOINT, ARTIFACT
  and PARTIAL_CONSENT. More cases may be declared up to 256. Expected utility
  and visible effect digests come from the independent original inputs, not
  a producer's self-description. The UI's fresh idempotency key is recorded;
  every other submitted field must equal the frozen original request.
- A table of actual permitted local actions and any required already
  canonical SOURCED_FACT observations. MODEL_RELATIVE tokens or an
  authenticated assertion cannot select a hidden private model. The driver
  waits only within original dates and the remaining original deadline.
- Six existing negative cases: stale source, revoked rights, cross tenant,
  resource bound, unsupported and incomplete. The driver does not create
  these conditions with privileged SQL or alter expected outcomes.
  Negative consumer calls must genuinely refuse, not succeed at cancel or
  another unrelated operation. Reading UNSUPPORTED/INCOMPLETE also requires
  subsequent native admission refusal. Fixture-kind provenance remains the
  operator's preexisting target declaration, not independent custody.
- The independently owned worker PID, start ticks and command hash. It must
  not belong to a stock launcher that tears down the entire stack when a
  child exits. Explicit authority must cover the physical kill/restart and
  the final stopped-worker state. It must separately cover consuming the
  existing original remaining construction allowance to its actual bound.

Native API/frontend runtime must retain `NODE_ENV=test`,
`FINNOR_ENVIRONMENT=ordinary_disposable`, and the existing Y3/Y1 ordinary
disposable profiles. Production builds are not production activation.
Launch/configuration belongs to the target owner, not this driver.

## Explicit guarded native execution

Only after real authority and the existing target are available:

`FINNOR_Z2_DISPOSABLE_E2E=1 /absolute/pinned/node22
/absolute/installed/finnor-os/scripts/project-z/z2/native-replay.mjs
--execute-native --target /absolute/target.json
--evidence-dir /absolute/new/native-proof`

Without the explicit switch, environment flag and target, exit 78 records
NOT_RUN before DB, Auth or browser access. Use a new evidence directory on
every attempt. Do not put credentials in a shell command or load a `.env`.

The driver uses separate browser contexts and the real mounted Work panel,
real bearer Auth, canonical consent/intake, independent original utility and
coalition checks, native admission, exact terms, per-participant Work reload,
local actions/observations, exact EFFECT consents and native materialization.
It can check NO_EFFECT consumption or prepare the original fixed
RIGHT_TRANSITION programme and read its exact one-step preimage. It never
runs or dispatches that programme. Nonzero modeled financial payments remain
part of the mathematics; the native Y3 financial adapter still refuses them.
This refusal is not permission to change utilities or fake a settlement.

The replacement worker uses a deliberate isolated environment. It registers
only the original construction job type, disables proactive scans, uses no
provider credentials, no Auth bypass and no listener, and checks the exact
tenant/Work set. Generic queue recovery is not tenant-isolated by registration,
so the exclusive DB prerequisite is mandatory. Unrelated live/retired jobs
refuse the run. The native compute permit retains its original policy,
fencing and expiry. The driver observes natural expiry after a hard kill;
it does not release, reset or shorten the original reservation/permit.
The browser likewise uses the exact receipt-bound executable and a new
owned HOME/TMPDIR, without inherited DB/Auth/provider secrets. Its contexts
allow only the declared frontend/API/Auth origins, block service workers,
WebSockets and WebRTC, and never attach to a shared browser.

After checking and admitting the original parent, it submits ordinary
same-Work descendants with the exact original meanings and original parent.
Every child must retain the original input, episode and deadline, reuse its
own duplicate delivery identity, pass the independent original oracle and
name the original checked parent as its actual compatible fallback. This
occupies, and charges, the existing four-attempt allowance through real
canonical worker jobs. The next submission must refuse with
`Z2_ORIGINAL_EPISODE_EXHAUSTED`. The still-current original parent then
reaches original terms/participant Work/consent use without a new allowance.
No quota or resource counter is changed by the driver. This is deliberately
not a free retry and is never authorized by an unfilled template.

Durable original events stop only the explicitly matched owned delivery.
Recovery retains original Work/input/episode/deadline/reservation, original
remaining allowances, increasing physical fences and UNKNOWN cost tails.
An interrupted consent/intake/link is repaired by exact canonical replay.
Withdrawal still invalidates subsequent use without erasing responsibility.
Only the owned replacement worker and browser contexts are stopped at cleanup.

Proof and restricted logs are local, with 0700 directories/0600 files.
Per-step durable evidence contains digests and original IDs, not credential
values. Retain failed attempts. Do not publish private raw targets or logs.
Money, human time and aggregate worker/browser memory remain explicit meter
gaps. This driver does not establish full 32×8 authenticated qualification,
ambiguous S6 effect recovery, protected admission, equipped comparison,
operational/financial 100×, production access or coordinator acceptance.
