# Total discovery v2 implementation contract

This is the first bounded public unit of the selected architecture. It does
not qualify the protected family campaign or establish general discovery.
The v1 additive-box path remains a separate, explicitly reused baseline.

## Data and owner boundary

The immutable authenticated user Work input contains a strict
`finnor.y5.work-specification.v2` document. It supplies the mathematical task,
not candidate code, a proof, an invariant or an algorithm-state choice.
The resolver reads that original Work input under the existing Work owner
authorization. It constructs the reference itself and binds the current
Work-input digest before any search.

The supplied task has arbitrary finite integer-list inputs, an integer
initial economic state, an exact transition expression, a safety expression,
and the least feasible initial-state objective. Every prefix, including the
empty prefix, must be safe. The first public specification is ordinary
prefix solvency. It supplies addition and nonnegativity, not a solution.
Other task meanings may exhaust the bounded search or lack any solution.

An absent semantic receipt produces `PUBLIC_DEVELOPMENT`. A present receipt
requires an externally configured policy, authorized issuer/key/scope,
matching tenant and definition digest, valid dates, an unrevoked identity
and a valid signature. A caller flag or local development signing fixture
does not establish independent acceptance. Missing or invalid configuration
with a supplied receipt refuses instead of silently downgrading it.
Even a signature under configured policy does not establish protected
campaign selection, independent policy approval or checker custody.

The S5 owner selects its entire bounded authenticated-principal episode
census at an immutable native commit-clock cut. It includes adverse,
corrected, REFUSAL, COST and UNKNOWN siblings. Overflow, unavailable commit
time, rights loss or a changing census refuses the cut. No caller list can
declare completeness. The pinned Y4 SELECT policies explicitly retain the
original principal's own rows. Foreign confidential rows remain hidden.

## Closed language and search

The initial language has integers, naturals, Booleans, products and lists,
with typed variables, constructors/projections, conditionals, arithmetic,
comparisons and a structural right fold. Algorithm state is separate from
the supplied economic state. Search includes scalar and product/list state
types and the initial, step and result expressions. There is no task-named
reserve operator, preloaded successful recurrence or arbitrary source text.
This first version does not claim arbitrary nested-recursion synthesis.

Propositions use semantic feasibility/safety atoms, integer comparisons,
truth, falsity, negation, conjunction, disjunction, implication and
equivalence. Integer terms include the quantified initial state, algorithm
output and grammar constants. The grammar is not exclusively a threshold
equivalence. Development examples and lawful episode subterms rank/filter
proposals, but cannot change the task or its domain.

Every finite rejected example records the actual mismatch. Proof failure
is UNPROVED, never a mathematical refutation. Candidate/AST/proposition/
proof/frontier/retained-byte caps and the original deadline apply before
expensive work. Exhaustion is INCOMPLETE, never problem infeasibility.

## Proof and executable contract

The Lean interpreter is the execution semantics. The checker obtains the
expected task independently, reconstructs the exact program and proposition
from bounded closed data, checks the theorem type, replays the supplied
proof object and inventories actual imports and axioms. Only the pinned
core profile and approved logical axioms are permitted.

The discovered lemma must occur in the uniform theorem's proof term.
The uniform theorem proves prefix feasibility and leastness for every
finite integer list. It supplies a feasible output for every input.
An explicit zero-list witness covers every size, including zero. A generic
proof relates recursive task feasibility to the complete prefix meaning.
The task has no candidate-selected extra assumptions.

The counted interpreter must equal ordinary denotation. Its primitive
charges include evaluated expression nodes, constructors/projections,
conditionals, arithmetic and fold iterations. Its checked bound is
`operations <= coefficient * input.length + constant`. Exact integer
arithmetic is a declared primitive, not a bit, memory or wall-time bound.

The capsule binds the owner specification, complete episode cut, canonical
program, proposition, grammar, interpreter/counting revision, source, proof,
transitive runtime/import inventory and checked cost constants. Execution
uses that same Lean definition and records actual input/output digests.
Lean's separate kernel replay is not another proof-system implementation.

## Registered falsifiers before implementation

The public library driver and authenticated Work/queue driver must retain:

1. Unavailable Work input, another principal/tenant's input, supplied program
   or invariant keys, absent acceptance, forged receipt, wrong scope,
   revoked key and changed source/census before publication.
2. An ill-typed variable, product/projection mismatch, excessive depth,
   hostile source/import text, noncanonical integer or oversized frontier.
3. An execution program or invariant changed after proof; a substituted
   expected task, implementation, proof object, grammar or interpreter.
4. Finite agreement without proof, a false well-typed conjecture, an unused
   lemma, a narrowed/vacuous domain, missed empty prefix or wrong cost bound.
5. Actual same-definition execution on empty and adverse nonempty inputs,
   arithmetic beyond machine integers, a fresh independently checked input,
   and a separately coded exhaustive original-prefix oracle.
6. Authenticated submit/replay/conflict, durable Work/store/queue completion,
   cancellation/late output and a mounted view that never revives stale
   private data after a Work/identity/rights change.

A reserve result is mathematical output for that task. It is not an S5
allocation optimum. Without a proved original-space semantic bridge or an
independently checked matching bound, no such owner claim may be emitted.
