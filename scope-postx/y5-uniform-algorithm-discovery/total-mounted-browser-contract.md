# Typed mounted bridge, registered before helper implementation

This is a proposed executable observation contract, not a mounted pass.
The parent exclusively owns the assigned visible browser and the serial native
slot. This helper-writing phase runs no server, browser, build or native job.
Keep the existing allocation v1 mounted harness unchanged and usable.

## Inputs and authority

The authentic total-owner driver creates two real accepted S3/S4/S5 episodes,
the adverse refused sibling, the specification Work, two recorded task Works,
the original queued discovery, actual claimant, checked capsule and two uses.
The bridge receives these exact references after the original two-use check.
It must require built API and installed-worker mode, the installed frontend
identity, and the actual current built API process. No source-only substitute.

Seed persisted Investigation contexts for these existing Works. A distinct
typed specification and task Work may be recorded through receiveWork solely
for browser submission and cancellation before a worker claim. Resolve its
source through the real specification endpoint; do not manufacture a source
reference, checked result or capsule. That cancellation is not physical
cancellation of a running native process.

## Prewritten observations and failure cases

1. Login through the real visible form and SDK, or explicitly continue its
   already authenticated session. Native focus/Enter or pointer actions only.
   No DOM click/eval, auth injection, direct product calls from browser code,
   response replacement, private controller call or alternate browser.
2. Open the actual checked Investigation, Canvas, then Focus Enterprise
   application. Observe the recorded source digest and PUBLIC_DEVELOPMENT
   acceptance. The fixture must never become independent acceptance.
3. Type an unfinished task Work draft. Across two completed lightweight owner
   polls, require byte-for-byte preservation. Record wire input keys, status,
   bytes and canonical state without auth headers or proof response bodies.
   Before the evidence action, no browser read may request capsule/history.
4. Load proof evidence through its real button and expand the proof disclosure.
   Require the explicit includeCapsule/includeHistory request and a real
   persisted capsule digest in rendered evidence, not merely a disclosure label.
5. Use the real checked method on both original task Works. Require exactly two
   additional COMPLETE uses, their native integer/operation results in the UI,
   independent additive all-prefix least-state results, and unchanged effects
   and reservations. Native operation count is compared to the canonical
   owner, not called an independently implemented cost measurement.
6. Hold a real original-owner response after production, switch through the
   persisted Investigation picker, release it, and require old source, result,
   capsule and form not to reappear. Transport failure must clear private data;
   remove only the owned abort interception before real reconnect.
7. On the separate cancellation Work, submit through the actual typed UI,
   observe QUEUED, cancel through its real control, and inspect CANCELLED,
   generation, finite counters and cancellation history in canonical SQL.
8. Return to checked Work, finish current phase, then let the parent perform
   its original task-source and P7 holdouts. Observe not current and no typed
   use action. Suspend only the disposable principal, require private data to
   clear, restore it, and require canonical active status before completion.

A missing field, wrong Work, lost frame delivery, stale ref, hidden pane,
failed screenshot, changed source, API refusal or deadline is a failure or
block, never a successful UI observation. The known campaignDeadline/deadlineAt
UI integration mismatch must be fixed by the parent before execution.

Before that repair, the owner E2E must require the shared read counter
`deadlineAt` to equal the persisted, unchanged campaign deadline. Campaign
cost and theorem-lifetime fields remain distinct. Control acknowledgements
must become visible only after their complete JSON is written, so a directory
watch cannot miss completion after observing a partial file. Abort interception
must be limited to this run's explicit loopback origin.

## Bounds and evidence

One browser orchestration has a 600-second total budget across both phases.
Individual CLI commands retain the previous 45-second maximum. The typed
bridge has one shared 1,200-second lifetime, not a renewed per-phase budget.
Original discovery deadlines, use allowances, claims and native bounds never
increase. Cleanup gets only 15 seconds and may only release the owned held
response, remove its abort route and restore the same disposable principal.
The bridge also restores its own principal/held response on close.

Write unique, private run directories under the supplied workspace evidence
directory. Retain action results/hashes, fresh accessibility snapshots, actual
screenshots, input/helper/build identities, wire metadata, canonical SQL
snapshots, phase receipts, failures and cleanup outcomes. Do not overwrite old
attempts. A scoped browser pass remains distinct from hosted auth, protected
qualification, live-native cancellation, cross-principal login and economics.
