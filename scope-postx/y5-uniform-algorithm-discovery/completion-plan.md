## Finite verification discipline

Use the existing end-to-end drivers, not post-code unit tests. New isolated
mathematical checks require a written failure model first. Before expensive
runs, register the actual source/runtime cut, case selection, expected
independent result, command, evidence destination and resource ceiling.

Allow at most two trials of the same predicate without diagnosis. A third needs
an observed cause, a repair and a new decision-log entry. Never reset a running
episode because its observer timed out. Run expensive native/build/installed
work serially. Retain original failed output. Reuse passed unchanged checks
instead of expanding a campaign without a material reason.

The coding run stops at verified software delivery or a precise retained
internal failure that cannot be resolved with available resources. It does not
wait ninety days or thirty-six months, and it cannot call that waiting period a
passed qualification. Draft publication must describe the actual gate state.
