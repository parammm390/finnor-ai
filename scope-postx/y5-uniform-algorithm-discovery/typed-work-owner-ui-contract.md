# Typed Work S5 and S8 controls, registered before UI changes

This is an observation/failure contract, not mounted evidence. No browser,
server, build, native invocation, install or full typecheck is authorized here.

## Same-meaning S5 baseline

The real action posts record-task-episode with only root, specification workId,
separate taskWorkId and the retained idempotencyKey. No caller values, answer,
acceptance or alternate ledger. Show the actual MODEL_ACCEPTED, REFUSED or
UNKNOWN response, exact model value when available, finite reference bounds,
rejected candidates/all-prefix evidence, costs and immutable request/result refs.
MODEL_ACCEPTED is model-only, not independent semantic/business acceptance,
protected credit, an all-size proof, an allocation optimum or effect authority.

Use the existing authenticated scope, pending-request identity and late-response
fences. A retry reuses its original body/key. Clear scoped output on source,
rights, Work or principal change. Do not show baseline results as proved native
algorithm use, or reuse a held-out future task as development acceptance.

Discovery still needs at least two distinct prior MODEL_ACCEPTED task Works
with the exact specification source, definition and acceptance policy. Retain
matching refusal/UNKNOWN/cost siblings. The UI cannot manufacture, infer from
allocation certificates, or locally bypass that server-owned gate.

## Actual v2 S8 dispatch

Expose the existing assign-evaluation, evaluate, s8-propose and admission commands
for both protocols, keeping their descriptions distinct. Assignment posts
discoveryId, a different evaluatorId and idempotencyKey. Evaluation posts only
evaluationId as the actually authenticated assigned evaluator, from that
evaluator's own accessible Work. Proposal posts discoveryId and idempotencyKey.
Admission is a fresh read with discoveryId and an exact S8 revision reference,
not a signed promoter command.

For S8 acceptance, assignment and proposal precede independent protocol
registration, which must precede native evaluation. Signed evaluation and
promotion remain with the separate configured S8 authority. The panel must
explain this order, not fabricate a protocol or accept post-hoc registration.

The UI neither creates signatures nor configures/impersonates an independent
S8 authority. Missing policy, wrong principal, expired protocol, refused or
incomplete evaluation and not-current admission remain actual refusals/unknowns.
PUBLIC_DEVELOPMENT and CHECKED_DEVELOPMENT never become semantic ACCEPTED,
protectedAdmission or production activation. No fake local admission success.
Changing the discovery clears its scoped assignment/revision forms and receipt.

## Finite mounted oracle for parent execution

Record two training task Works, for example [-1,1] and [-2,-1,4], through the
real S5 command before submit-total. Retain UNKNOWN [-5000] as adverse evidence.
Do this separately for every distinct specification source, including the
separate cancellation specification. Allocation-only episodes do not qualify.
Never record future [-4,2,-3,8] before discovery; require it absent the complete
development projection and use it only as a later held-out task.

Through actual visible controls, check baseline response/evidence and retry
identity, register assignment as discoverer, switch to the evaluator's own
persisted Investigation and run its evaluation ID. Observe actual typed result
or refusal. Propose to the separately configured owner and freshly check its
exact returned S8 revision reference. Inspect canonical owner/S8 ledgers, source
withdrawal and identity fences. Native evaluation consumes the original finite
use allowance and its 28.5-second invocation, not a new browser grant.
