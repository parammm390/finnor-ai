# V2 evaluation and disposable S8 contract

Registered before implementation. This extends the existing typed owner unit.
It does not establish protected custody, semantic acceptance, production
admission, execution grants, reservations, S6 effects, or economic improvement.

## Failure model

1. A v1 allocation capsule, assignment, signed protocol, evaluation, or admission
   must not satisfy the v2 typed-theory profile, or the reverse.
2. The proposer must not evaluate itself. An authenticated, active, distinct
   evaluator must have current authority over the specification and task Work.
   Assignment is durable before native execution. The external S8 evaluator
   registers its signed protocol before that execution.
3. Caller-supplied values, definitions, proof results, source subsets, or
   unregistered native-use references are not evidence.
4. Evaluation uses the original recorded typed task, the exact owner-expected
   kernel statement, same-definition execution, and S5's independent
   task-meaning interpretation of every prefix, including the empty prefix.
   The source meaning comes from matching original S5 typed-task episodes;
   it is not scaled allocation objectives or the v1 allocation-subset oracle.
5. First evaluation start durably freezes its invocation deadline. Its native
   use consumes the discovery's existing finite use allowance. Concurrent
   starts, retries after a lost process, and incomplete physical outcomes do
   not receive automatic reexecution or a new deadline.
6. A completed evaluation is immutable. Replay rechecks current authorization,
   source, specification, original task, capsule, and assignment bindings.
   UNKNOWN is not supporting evidence.
7. Discovery campaign expiry is not theorem expiry. Assignment and candidate
   validity are separately bounded. Current semantic-policy expiry, signed S8
   policy/key expiry, Work, rights, source/runtime, cancellation, and P7
   invalidation still stop new uses and current admission.
8. Promotion goes only through the existing authenticated S8 service with a
   separate evaluator signer and promoter signer. Self-signing, substitutions,
   post-hoc protocol registration, expired keys, and cross-profile receipts
   fail closed. Every successful result remains disposable and unprotected.
9. The v2 source closure is complete, not a selected prefix. It includes the
   transitive owner closure and S8 implementation. Bound it explicitly by
   4096 pins, 1 MiB serialized pins, 16 MiB per source file, and 64 MiB total
   source bytes. Missing, extra, duplicate, changed, or oversized pins fail.
   Rehash actual bytes at every serve, including a v2 closing source check
   after native-proof resolution. Source-pin collection uses at most 16 I/O
   operations concurrently. The legacy lifecycle policy retains its
   existing base closure limits; v2 additionally binds its complete larger
   closure in the candidate and separately signed typed consumer policy.
   Other Y1–Y4 schemas and source bounds do not widen.
10. Loss after S8 acceptance must replay the registered candidate rather than
    mint a replacement. Revocation and restart retain history and do not
    reactivate a withdrawn candidate.

## Prewritten verification

`finnor-os/scripts/postx/y5/verify-total-s8.mts` is an artifact-producing extension
of the real typed owner HTTP/queue E2E, with a finite standalone wrapper. It
requires its parent hook and fails if the hook did not produce S8 evidence.
The extension uses the actual separate disposable S8 services and signing
roles. It checks complete large closure, pre-registration, self/foreign denial,
native typed-task evaluation, immutable replay and counters, cross-profile and
result substitution, separated promotion, source-pin substitution, restart,
P7 invalidation, and sticky revocation.

Each run retains registered inputs, observed HTTP results, native evaluation,
signed protocol/evaluation/admission receipts, source pins, durable rows, and
rerun information. Initial preflight is a missing-module red. No native,
server, or build run is authorized while another worker holds the heavy slot.

## Qualification

The owner driver runs the mounted current phase after its original two-use
assertion. It then runs the optional S8 extension before P7 invalidation and
calls the extension's invalidation check afterward. The durable use oracle is
two original uses, two additional mounted uses when enabled, and one additional
S8 evaluation use when enabled. Nested cleanup closes S8, the mounted bridge,
and the database even when an assertion fails. None receives a reset deadline.

Implementation and static checks are provisional until the integrated owner
and S8 native E2E pass against the current sandbox, source closure and installed
assets. A passing disposable test is not independent model diversity or
protected acceptance.
