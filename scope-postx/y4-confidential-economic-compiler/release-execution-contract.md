# E1 execution details

The registered release entry may take `--original-episode` pointing to a
retained, successful, current-profile synthetic B1 numerical episode. It does
not rerun that computation, replace its originals, renew its deadline, modify
its owner files, or erase/refund its disclosure history.

Before implementation, the concrete failure predicates are:

1. Every native recipient export contains exactly that recipient's declared
   outputs. Substituting a different participant identity must refuse.
2. New sessions for the same source must refuse after completion, including
   changed functions, family labels, source versions, grant handles, and Work
   labels. A new caller-supplied label is not a new source.
3. An expired or revoked current local owner cut must refuse export of a
   previously completed result. Tests retain the original cut and append
   adverse cut versions only inside the new episode's private directory.
4. Every failed prepare must leave the prior private state, original deadline,
   receipt and disclosure reservations unchanged.
5. Stale/missing evidence, a changed implementation identity, an unknown
   synthetic original, an unexpected refusal, or any accepted requery fails
   the entry. An old result with absent private state cannot pass.

This verifies participant-local release controls against actual native B1
outputs. The separate installed lifecycle verifies the authenticated API,
canonical consent revocation and derivative RLS. Neither is independently
administered or a protected assignment.
