# Final offline runtime reconstruction

This extends the byte-materialization contract, not upstream build reproduction.
Retain all previous packages, installations and failed attempts.

- Package the exact installed backend dependency closure, the emitter and embedded
  PostgreSQL driver/platform, and complete packages traversed by the actual mounted
  WORLD browser build. Keep package metadata and redistribution licenses.
- Record every byte, mode and contained relative link. Missing required packages,
  substituted browser dependency bytes, escaping links and omitted archive members
  must refuse. No registry resolution or install scripts run during reconstruction.
- Package the pinned scientific distributions used by the actual S3 and S5 owners,
  including their transitive Python dependencies, native wheel libraries, licenses,
  CPython executable and standard library. Exclude credentials, pip and byte caches.
  Isolated scientific processes must resolve these fresh packaged modules, not the
  donor virtual environment or host third-party packages.
- Reconstruct into new empty roots. Content/mode deduplication may link only bytes
  first materialized from the verified archives within this reconstruction. Never
  hardlink a donor installation, repository or dependency tree.
- Verify and retain every original base blob, tree and commit in the fresh Git
  object database. The default worktree materializes the exact installed source
  closure plus the complete Y4 overlay; unrelated base files remain reconstructible
  from those local objects. `--full-worktree` also expands every base file when
  capacity permits. This never omits base bytes or substitutes a donor checkout.
- Verify every archived dependency member, while materializing backend runtime
  packages including their type declarations (optional debug maps may remain
  archived) and the actual mounted WORLD build's frontend input files,
  package metadata and licenses. All complete frontend packages remain in the
  pinned archive; `--full-dependencies` expands every member, including debug
  maps. This is not a Next
  server deployment or an unscoped npm installation. Missing actual build inputs
  still fail before the browser or native qualification can pass.
- Measure space for unique materialized bytes, new Git objects, emitted programs
  and the finite episode before participant preparation. Missing capacity refuses
  before exposure. Do not delete retained artifacts to make space.
- A split-root reconstruction may put its fresh Git metadata/object database
  under its new runtime root using Git's separate-git-dir support. The worktree
  points only to those freshly verified objects, never donor Git storage or
  alternates. Count working bytes and Git object/index bytes on their actual
  devices. Record this layout and the Git host-tool dependency.
- Rebuild emitted entrypoints from the complete original Git base plus final Y4
  overlay, compare their hashes, and run the actual full owner/S8/browser lifecycle.
  Report Node, Python, Linux/glibc, OpenSSL and agent-browser/browser host dependencies.
- Local common-host reconstruction is neither protected qualification, comparison
  against equipped X, production admission, nor independent upstream binary builds.

Failure cases include truncated or oversized archives, duplicate member names,
incorrect modes or hashes, unknown symlinks, missing optional-at-runtime native
modules, missing licenses, wrong interpreter ABI, ambient Python imports, incomplete
frontend resolution, internal links accidentally targeting donors, source drift,
capacity exhaustion and child-process or browser failure. Keep each failed result.
