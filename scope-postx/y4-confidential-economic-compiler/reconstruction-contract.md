# Reconstruction custody and failure model

## Final evidence binding and bounded storage

A declared PASS is not a completion proof. The sealer rejects wrong-case,
duplicate-role, stale-runtime, stale-driver, incomplete-stage, missing-fault and
unbound reconstruction observations. Each of the eight engineering proofs
names and hashes its actual public observations. Product cases bind the executed
installed manifest and captured driver cut; finite cases bind their Python
identity and helper bytes; reconstruction binds unpacked source and emitted
entrypoints. Static review and type checks name their actual source dependency
cut. Documentation-only changes never substitute for an executed runtime cut.

Negative packaging episodes invoke the real sealer with substituted case or
source observations from retained attempts and require refusal, preserving the
attempts. A partial product stage list is not a completed installed lifecycle.
These checks are local attestations, not a protected or security qualification.

The final negative episode copies, never overwrites, current public evidence.
It re-pins each deliberate mutation through its observation, proof and gate
index so semantic checks, not a trivial stale hash, must refuse. Registered
cases are wrong product case, stale executed driver, incomplete product stages,
missing protocol fault, duplicate gate, duplicate observation role, open actual
individual review behind an aggregate PASS, nonpassing actual individual review,
and stale reconstructed runtime source. Require each exact refusal before output
allocation. Preserve every variant and verify original evidence bytes unchanged.
This episode runs against actual retained observations; it does not substitute
mocked product, reviewer, native or reconstruction successes.

Fresh Git objects may be stored directly in a pack to avoid loose-object
filesystem block amplification. Independently compute every blob/tree/commit
identity and the pack trailer, then have Git index and verify the fresh pack.
Missing ancestor history remains explicit. Keep all base objects, including
objects for deliberately unmaterialized source files. Capacity must include
compressed object bytes, pack-index overhead, trees and the working closure.

The original J1 entry was absent. Its initial implemented scope is an independent
byte reconstruction of the complete base source tree plus Y4 overlay and the
pinned native compiler/runtime closure, followed by a fresh three-party native
calculation. It must not be called full installed-product reconstruction.

Before implementation:

- Package the actual pinned base tree, its original commit bytes, all changed
  source and explicit native compiler/library/circuit bytes. Do not borrow a
  donor checkout, Git alternates, symlinks, hardlinks or dependency directories.
- Verify both archive digests and every member's declared hash. Reconstruct Git
  blob/tree hashes from the base archive and match the pinned base tree. Verify
  the exact original commit object hash. Full ancestor history is not included.
- Reject absolute paths, `..`, links, duplicates, special files and archive
  members not declared in the relevant inventory. Never extract private state.
- Only use a new absolute reconstruction directory. Never overwrite an
  existing reconstruction or user file. Preserve failed attempts.
- Run the reconstructed compiler, independent checker, participant runtime,
  independent rational oracle and copied backend in fresh processes with a
  clean Python import path. Native participants use new local inputs and setup.
- Keep inputs, local TLS keys, salts and native logs under private evidence.
- Compare all original package bytes after reconstruction. No original state,
  source, installed copy or preprocessing is resumed.
- Report common-host custody, host Python/OpenSSL/kernel dependencies and absent
  complete Node/frontend clean-install proof explicitly. Do not infer S8,
  separately administered qualification, production or economic improvement.
- Preflight space. A capacity refusal is a retained engineering failure, not an
  external qualification block or permission to remove unrelated assets.

## Complete offline product reconstruction, before its implementation

With additional space available, package both complete existing Node dependency
trees, including frontend dependencies, npm slots, package notices and native
addons. Record every file byte and internal relative link. Reject secrets,
external links and special files. A reconstruction may create only declared,
contained links into its freshly unpacked dependency trees, never donor links.

Recreate base Git blob/tree/commit objects from the verified archive rather than
Git alternates or donor object reads. Apply the exact Y4 overlay, then rebuild
the emitted API/worker from that reconstructed source with byte-copied
dependencies. Verify emitted entrypoint hashes against the original installed
cut. Run a fresh full API/queue/native/recipient/Work/browser episode from the
reconstructed source and dependencies.

This is an offline byte-materialized installation of recorded assets, not a
claim that npm redownloaded or independently reproduced upstream packages or
that native C++ binaries were rebuilt. Record host Node/Python/OpenSSL/browser
tool requirements. Browser automation may use the installed verification tool,
but no donor product/frontend dependency may be resolved. Independent deployment
administration, protected qualification and production authority remain separate.

The first full attempt exposed Node's realpath package lookup requirement: each
fresh backend/frontend package root must itself be named `node_modules`.
The corrected bootstrap is captured and hashed before execution.

For durable custody of a completed tmpfs reconstruction, copy its result,
bootstrap and product-episode evidence only into a new private local archive,
without following links. Keep the complete source/runtime packages separately.
This is retained execution evidence, not another installed runtime. Preserve
the original reconstruction and failed attempts, and publish no private member
names, values, credentials or per-private-file hashes.
