# POSTX.Y1, Economic Action-Theory Compiler

Y1 constructs a finite `EconomicActionTheory` from canonical observations,
declared invariants and explicit meaning/consent references. Callers supply
neither transition bodies nor composition laws. X5 policy learning, schedules
and named operator templates are not the implementation.

The exact profile and preregistered acceptance contract are in `profile.json`,
`DESIGN.md` and `verification-plan.json`. They remain unchanged by failed runs.

## IMPLEMENTED

The authenticated owner path is:

`API → durable job → actual createWorker → sparse exact synthesis → separate
Python Fraction checker → immutable artifact/envelope → typed S8 development
admission → P1/S4 PlanGraph → canonical S5 reservation → native S6 obligation
and BusinessEffect → separate canonical S7 observation → maintained WORLD Work`.

The checker independently searches the finite hypothesis space, verifies
identified denotations and nonvacuous composition laws, and binds its receipt to
the exact problem, body, profile, checker source and interpreter executable.
Only its exhaustive finite check can justify `INFEASIBLE`.

Statuses are `CANDIDATE`, `CHECKED`, `INCOMPLETE`, `INFEASIBLE`, `UNIDENTIFIED`,
`UNSUPPORTED` and `UNKNOWN`. Queue, invalidation and cancellation states are
separate lifecycle states. Failed processes and resource exhaustion are not
infeasibility proofs.

The first owner adapter supports only disposable internal reservation-right
transitions. A single original S5 capacity envelope stays reserved while its
rights distribution changes. Exact action PlanNodes, original obligations,
effect identities, owner history and observations survive retries and
cancellation. No generic action/plugin opcode or external economic adapter is
granted.

P7 invalidates mutable heads on Work inputs, evidence versions and authority
revisions. The retained closure identifies affected and unaffected semantic
preimages. A changed theory must be independently checked again before use;
keeping an unaffected preimage is not permission to execute an invalid artifact.

### Reproduce engineering verification

Use Node 22 and `/usr/bin/python3` with the standard library on Linux. Do not
point these commands at any hosted database or real economic context.

```sh
# From the independent source checkout:
npm ci --ignore-scripts
cd finnor-os
npm ci --ignore-scripts
npm rebuild fs-ext embedded-postgres
npm run db:bundle
npm run openapi
npm run build --workspace @finnor/api
node --import=tsx scripts/y1/build-runtime.mts
FINNOR_Y1_BUILT_API=1 FINNOR_Y1_EVIDENCE_DIR=/absolute/new/installed-evidence \
  node --import=tsx scripts/y1/run-installed.mts
```

For the mounted campaign, keep the first process running and execute the second
command in another terminal:

```sh
FINNOR_Y1_EVIDENCE_DIR=/absolute/new/browser-evidence \
  node --import=tsx scripts/y1/run-mounted.mts
FINNOR_Y1_EVIDENCE_DIR=/absolute/new/browser-evidence \
  node --import=tsx scripts/y1/browser-checks.mts
```

The fixture creates ordinary input declarations, local identities and a
loopback-only transport. It records its ready state in `browser-fixture.json`.
The browser signs in normally. Controls only delay genuine replies, run native
queue ticks, introduce explicit steering inputs and read canonical SQL.

The source packet contains a complete committed-tree archive, the exact original
commit object and their digests. It excludes dependencies and parent history.
`scripts/y1/reconstruct-source.mjs` recreates an independent shallow checkout,
checks the complete Git tree and commit preimages, then requires fresh lockfile
installs before any build. `scripts/y1/seal-local.mts` refuses incomplete final
installed, browser or reconstruction reports and keeps protected gates unmet.

The bounded reconstruction runner may recycle this task's disposable dependency
storage, but runs both `npm ci` commands before any build or producer. It verifies
all workspace links resolve inside the reconstructed checkout. To respect the
frozen disk bound, it can rebuild into existing task-owned generated output
directories. That storage reuse is recorded separately from source and dependency
independence. It repeats both the installed campaign and the mounted browser path.

The emitted worker requires the delivered canonical source tree and a fresh
lockfile install. Some pre-existing owner adapters register `tsx` through
`@finnor/source-custody`; this is not a source-loader-free claim for every legacy
adapter. The Y1 compiler and checker used by the worker are emitted/pinned assets.
