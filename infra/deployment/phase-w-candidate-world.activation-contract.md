# Phase W candidate-world activation contract

**DESIGN ONLY. No world is registered, admitted, provisioned or running.**
`phase-w-isolated-nonproduction-candidate` is a proposed key, not an admission
ID. The accompanying `phase-w-candidate-world.design.json` is inert source.
It adds no loader, route, credentials, IAM policy, admission port, startup hook,
deployment or executable activation procedure. Merging it or flipping a flag
cannot authorize any action.

## Selected boundary

The current choice permits an isolated nonproduction **design**, using only the
direction of an existing independently authorized Linux host with delegated
cgroup v2 for development-native fixtures. No host or candidate-world identity
has been supplied. Existing production Fargate, routes, roles, secret maps,
release guards, database policies and traffic remain unchanged. No new host,
cloud resource, credential, signing key, paid call or consequential effect is
authorized.

Development-native receipts stay development-only. A future actual human/field
world needs its own genuine admission, actor and data contracts; a DEV fixture,
disposable admission, model response or signed summary cannot become protected,
human, field or full-PRD proof.

## Activation is closed until every applicable prerequisite exists

1. **Separate implementation permission and genuine world admission.** Obtain
   explicit permission for a specific nonproduction implementation and actual
   world identity. Require current signed, time-bounded admission; separated
   existing proposer/evaluator/promoter authority and key fingerprints;
   independently read-back exact source/runtime closure; protected-event
   journaling; and a recovery contract. No self-bootstrap, new keys, invented
   admission IDs or reuse of disposable authority as protected authority.
2. **Qualified, independently authorized host.** Bind the actual existing Linux
   host, private work root and admitted resource profile. Prove delegated
   cpu/memory/pids controls, pre-execution membership, privilege/FD isolation,
   an actual absolute monotonic kernel deadline, and physical stop/drain with
   unknown-stop custody retained. Current Fargate cannot be relabeled as that
   delegated per-child mechanism. Source design is not host qualification.
3. **One admitted existing IAM session and model ARN.** Bind exactly one
   existing in-Region foundation-model ARN in selected Region `us-east-1` to
   non-streaming Bedrock Converse/SigV4 and `bedrock:InvokeModel`. Require the
   already-resolved existing session's admitted source, actual role/identity,
   expiration and lifetime pins through the bounded attempt and drain. No
   default credential chain, `credential_process`, external provider,
   refresh, STS/role assumption, retry/fallback or cross-Region route may run.
   No credential material belongs in this manifest or in a guest. Ordinary
   production adapters and roles remain unchanged.
4. **Explicit spend and live-call permission.** Supply the actual authorized
   spend budget and separate explicit permission for any live/paid call.
   Require mandatory fenced P3 capacity, S5 reservations/holds, a qualified
   bounded request/body path and an honest cost profile. Missing usage or money
   stays unknown, not zero; ambiguous provider effects retain owning holds and
   cannot authorize automatic replay. Today's authorized paid-call cap is zero.
5. **Actors and isolated data.** Supply authenticated actor identity, real
   consent, accepted terms, the actor/roster contract and a scoped nonproduction
   data/isolation/retention contract. No production data, traffic, credentials,
   secret map, storage, queue or database authority may be reused. Future
   human/field proof must satisfy the actual required PRD pairings, feedback
   root and time ledger with genuine human acts, never model-generated
   consent, verification, judgment or completion.
6. **Explicit logging posture.** Invocation/content logging and external
   telemetry are disabled in this design pending explicit posture. Actual
   cloud logging state is unknown. Verify it and obtain the data/actor-approved
   posture before calls; never assume this JSON changed provider settings.
   Do not toggle shared production logging. No prompts, responses, credentials
   or personal data enter telemetry; approved audit evidence requires its own
   custody/access/retention contract.

Any missing, stale, mismatched or unobservable prerequisite refuses activation.
These requirements describe future checks; this source adds no checker or
authority that can satisfy them.

## Qualification and production stay separate

The DEV-native lane cannot credit the future human/field lane. Neither lane's
existence alone proves the full PRD, installed/browser/cold/campaign gates or
production release. Missing actual Linux-world, qualified Z release and
competitive-roster references remain null; they block W054/W056 comparison,
not unrelated engineering, and never grant authority. No agent may invent them.

Production release remains blocked until every existing release requirement is
satisfied on the actual authorized source. This design weakens no production
route, IAM role, mutation inventory, admission policy or guard.
