# Additive owner consumer semantics, before implementation

S2 will expose a separate versioned observational-profile/proposal adapter. It
rechecks the actual S1 pin and source permissions and preserves each supplied
joint-law/support premise. It never calls or relabels a binomial protocol.
S3 will explicitly accept the supplied graph/query representation against its
current immutable variable/unit metadata, then persist a model-relative
identification assessment in its existing private artifact store.

S4 will persist an acquisition **planning** review in its existing store. Where
the original mandate contains finite deliberation utility, it compares the
owner's declared value of an accepted conditional result with the registered
acquisition cost and delay, under the original remaining episode. These are
supplied model-relative utility terms, not independently observed information
value or wealth. Missing terms produce unresolved value and WAIT, never free
information. A positive review is `ACCEPT_FOR_PLANNING`, not a physical
instruction, new reservation, admitted instrument or effect. Existing S4
WAIT/STOP synthesis and branch choice still execute. The integration oracle
uses a declared value of 100, costs of 2 versus 200, and a delayed alternative
whose declared delay cost exhausts that value. S6 UNKNOWN must prevent the
corresponding owner branch, and must not be settled by this review.

# Concrete owner seam, before shared edits

The authenticated principal and tenant come from the existing API context,
never request receipts. A current existing `evidence_execution` Work and its
immutable input revision are resolved through the canonical Work tables and S1
resource authorization. The R4 adapter does not create a financial ledger.

## Writers and resolved inputs

* **S1:** `loadEnterpriseBeliefView`, `validateBeliefViewPin`,
  `authorizeBeliefResources` and source-scope authorization resolve actual
  roots/source versions/series/rights. Source bytes are access/provenance, not a
  scientific joint law or positivity proof.
* **S3:** a new versioned R4-owned graph/query profile binds explicit supplied
  ADMGs, variable units and an existing immutable S3 model's owner metadata.
  `readEnterpriseInterventionMetadataForObservation` resolves that metadata.
  No FLOAT64 coefficient determines an ADMG edge. This ordinary authenticated
  declaration is development accepted, not protected causal qualification.
* **S7:** `readEnterpriseEconomicRecord` resolves the registered estimand
  preimage, target, population, intervention/horizon and owner mandate identity.
  Preregistration and source gaps remain visible; attribution is never granted.
* **S2:** a new observational acquisition adapter calls S1 for actual permitted
  source handles and keeps selection/measurement/linkage/support premises.
  It registers observational collection proposals rather than inventing an
  unrelated binomial protocol. Existing `designEnterpriseExperiments`,
  validation and realization contracts remain unchanged.
* **S4:** `readEnterpriseControlDecisionContext` resolves the actual incumbent,
  utility, original episode, model, instruments and outstanding obligations.
  R4 proposals add exact supplied collection cost/delay and a declared mapping
  to an existing compatible inquiry or wait/stop path. S4's ordinary
  `synthesizeEnterpriseControlProposal` / `chooseEnterpriseControlBranch`
  execute that owner choice. No grant, horizon or deadline is renewed.
* **S5:** `readEnterpriseAllocation` and `validateEnterpriseAllocation` resolve
  current clearance, selected policy, resource envelopes and reservations.
  The committed `p2_grant_usage` same-unit native-attempt counter is reused
  transactionally, under the S5 portfolio lock, so R4/P2 cannot spend separate
  copies of one envelope. Collection resource checks do not reserve capital.

## Durable and current-use readers

The additive API owns profile registration, submit, read/status, historical
inspection, cancel, revision and consume. Its strict bounded JSON contract
admits references or typed input only, no paths/code/pickle/credentials.
R4 SQL records own immutable profiles/inputs/artifacts/history and physical
attempt state, all tenant/principal fenced. The canonical jobs table owns the
actual protocol/token/fence/lease/delivery. A registered R4 handler invokes
separate application-configured producer and checker executables under the
original episode/deadline, S5 debit and actual compute leases.

Submit, claim, check acceptance, publication and consume re-resolve Work,
principal/rights, S1 pins, S2 profile, S3 metadata, S7 estimand, S4 utility,
S5 reservation/resources, source/schema/method/checker identity. Publication
uses a short SQL fence with locked canonical revision and principal rows.
R4-specific P7 dependency keys identify affected profiles/runs/claims only.
Revision never promotes prospective evidence; source/population/support readback
is rechecked by a new run under the original remaining episode.

## Decisive expected readback

An actual ordinary-role Work selects the necessary joint-data acquisition over
a cheaper incomplete marginal, reaches y0 and independent derivation/data/
minimality checks, persists all masks, then invokes S2/S3/S4/S5 consumers.
The existing Work renders the conditional formula and exact registered price.
No protected receipt, observed acquisition, point estimate or wealth credit is
fabricated. Unsupported/checker/invalidation/budget failures execute compatible
S4 wait/stop where current; when no admitted acquisition fallback exists, that
precise absence remains a gap alongside the actual ordinary S4 disposition.
