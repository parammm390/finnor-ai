# Preregistered mounted Work review

The additive child is `IdentificationPlanPanel` inside the existing
`EvidenceWorkbench`, reached through `CanvasDocument`'s `evidence_execution`
case. It is not a separate page or a financial verification status.

The authenticated `identification-plans/work` operation resolves the caller's
principal-specific profile head and newest run for the exact Work and root.
It rereads current owners before exposing a query, menu or accepted plan.
Only a separately checked immutable PLAN can supply a displayed functional.
Queued candidates are never projected as accepted output.

The display includes the exact query/population/intervention/time/units,
registered menu cost and second-based delay, selected and alternative masks,
per-graph functionals and law/support/collection conditions, complete menu
coverage and rejection reasons, common-functional basis, currentness,
original grant/deadline, gaps and actual native receipts. Planning acceptance
does not permit collection, create a reservation or supply an effect estimate.

Before implementation, mounted failure predicates:

* Missing Work, root mismatch or principal-specific profile must not reveal
  another Work's profile.
* A changed token, principal, Work, root, source/authority invalidation or
  hidden page immediately fences and clears private output. An outstanding
  response from the previous generation cannot restore it.
* Failed revalidation clears values rather than retaining a stale formula.
* An original expiry clears the view even when no polling response arrives.
* COMPLETE is a search lifecycle label, never VERIFIED field or financial
  evidence. CONDITIONAL remains visible beside future collection premises.
* Controls use only authenticated registered refs. No user-supplied executable,
  arbitrary program, new grant or automatic physical retry is available.
