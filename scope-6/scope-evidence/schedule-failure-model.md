# Durable S4 delivery, preregistered before implementation

Observable contract: an authenticated native S6 obligation can be submitted once to the existing command/workflow/job queue with its unchanged concrete request, owner signature, canonical effect and S4 business start. Compatible workers may claim it only when due. The protected broker checks the exact current workflow claim, generation, run version and durable job delivery before mutation. Cancellation/pause or a stale claim cannot acquire a fresh effect. A possible attempt remains unsettled until independent protected readback and native S5 reconciliation; scheduler or worker restart cannot repeat a recorded mutation.

Plausible breaks: recording only an in-memory timer; job insertion outside the command transaction; changing the request under an existing obligation; an old binary claiming a new step; an early queue delivery bypassing S4 timing; a stale worker dispatching after cancellation; dropping possible delivery after lease loss; marking a queued/acknowledged step complete; queue retry invoking a second PATCH; or permitting direct broker/API dispatch to bypass an existing cancelled schedule.

Missing coverage: the existing native dispatch/crash test owns the broker, protected readback and S5 settlement, but never submits a durable workflow or starts the actual JobQueue. Extend that authoritative owner E2E with separate fresh native fixtures for queued delivery/recovery and pre-effect cancellation. Each uses a real ordinary-role PostgreSQL queue, separate compatible worker processes, independent provider request records and SQL readback. No test-only production interface, flag or fake claim is required. The worker entry point is a test harness around the production queue/handler.

Evidence/oracle: literal expected dose 0.15; exactly one provider PATCH; zero PATCH for cancellation; exact persisted S4 not-before timestamp; unchanged canonical effect/hash; duplicate scheduling returns the same command/run/step; source/runtime pins; physical job/step claim rows; worker PIDs and terminal statuses; actual protected readbacks and receipts; S5 resource envelope remains held with unmetered costs; workflow completion follows all member observations and S5 settlement. Wrong-record/null challenges stay unresolved. Keep the original direct-dispatch cases. Run baseline before adding the production schedule API: its absence must be visible as HTTP 404, not misrepresented as an exploit.

Validity domain: existing single-dose conditional JSON method, disposable independent signing roots, local TLS provider contract and development header authentication. This adds durable native delivery evidence; it cannot certify production credentials, live provider semantics, OS-separated native services or human-reviewed releases. Current owner facts are bounded freshness witnesses, not an atomic lock on remote provider acceptance. Recovery is read-only after a locally possible dispatch. Exhausted recovery preserves the step, native commitment and protected history for operator takeover.
