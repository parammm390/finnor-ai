# W1 scientific reconstruction failure contract

Registered before changing the numerical requirements or cold installer.

The observable contract is that a separately installed W1 scientific environment
has exactly the full existing hash-locked distribution population, with its real
modules and metadata inside the new environment. Its interpreter distribution,
all installed assets (including executable bytecode), and observed external shared
libraries must be bound to recorded bytes before and after owning execution.
This is a packaging prerequisite; it does not establish native, field, economic
or protected-execution qualification.

Credible failures include a floating transitive dependency; an extra or missing
distribution; a venv entry resolved to the base executable; metadata or module
paths escaping to a donor environment; changed base/stdlib or package bytes;
unrecorded symlink targets or special files; duplicate/unhashed lock entries;
bytecode writes during execution; incompatible/missing native dependencies; and
a hung installer or observer. Failure, timeout and every original receipt remain
visible. No missing cost or identity becomes zero or PASS.

Existing coverage checks only the five direct versions and two module origins.
It does not detect the already observed complete-population mismatch against the
retained upstream hash lock. The primary regression is a real isolated Python
process observing the current environment before the fix, then the same observer
against a fresh environment installed from the complete hash lock. The final
owner proof remains the original emitted and cold API/worker/scientific journey,
with the unchanged mathematical oracle and original business deadlines.

There is no test-only product export or injected success. The delivered runtime
attestation CLI is called by the real cold reconstruction and source-freeze
tools. The expected package set comes from the original independent hash lock;
observed versions, locations, interpreter and loaded-library paths come from
the actual child process. File populations are read independently from disk.
