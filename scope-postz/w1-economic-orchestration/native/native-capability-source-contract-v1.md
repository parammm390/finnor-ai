# Existing P3 native capability revision: failure contract

This is an ordinary-disposable, non-authorizing attenuation of the registered
exact-native equipment. It is not a general model-acquisition port, S4 mandate,
S5 funding source, S7 invoice or protected-method admission.

The existing P3 operator-owned `compute_resource_policies` row for `native:p2`
already carries its configuration provenance in `source`. A deliberately tagged
`finnor.w1.native-capability.v1:` value may serialize a strict bounded immutable
revision there. Legacy plain provenance strings retain existing behavior.
No request, source document, fitted response or generated programme may write
or supply this configuration. W1 only reads it on its existing transaction;
only the original P3 configuration owner may change it.

The revision names the required registered model identity, a native-attempt
cost multiplier of at least one, a conservative nonnegative stage latency
planning allowance and optional exact original latency-receipt references.
These terms may only remove native methods or increase conservative cost/time.
They cannot introduce a method, lower S4's price, enlarge a physical capacity,
change a parent budget/deadline, mint/release a grant or dispatch an effect.
The multiplier is explicitly an operator-supplied finite planning proxy, never
observed monetary billing. Original paid debits remain one native-attempt each.

Unknown model identity disables all unimplemented methods. A minimum complete
native chain whose supplied cost exceeds the original maximum loss reduction
must STOP incomplete, not spend a CONTROL merely to justify work. A latency
allowance that does not fit the original remaining time similarly cannot be
selected. Existing checked accepted output and unresolved physical obligations
take precedence; an attenuation never clears UNKNOWN or erases sunk costs.

The complete tagged preimage is frozen into the runtime configuration pin.
Price, model and latency terms have distinct dependency fingerprints. An old
fit/capsule cannot be reused under the new configuration. Fresh actual claim
and subsequent original fallback/STOP are required; a changed digest alone
does not qualify. Latency evidence must be read from actual original attempts,
not invented elapsed-time samples. Observed latency is not a certified future
lower bound or a causal effect estimate.

Before code, reject: malformed/oversized tagged JSON; a multiplier below one;
future/as-yet-unavailable revisions; a declared model falsely called executed;
an absent/mismatched latency receipt; hidden source text instructions; fallback
ignoring disabled entries; a stage matcher resurrecting unavailable methods;
same revision identifier with changed preimage; accepting work after its clock
expires; clearing pending/UNKNOWN work; lowering cost; granting funding; and
unrecorded operator/fixture configuration changes.

The owning W014 journey independently exercises PRICE, MODEL and LATENCY.
PRICE and an unavailable MODEL may honestly select STOP/incomplete. LATENCY
must use a new actual native selection under the new frozen configuration and
retain both the historical policy and its charges. Independent reconstruction
checks exact originals, old-capsule rejection, the next real selection and the
entire parent/grant exposure. All monetary/field/protected gates stay separate.
