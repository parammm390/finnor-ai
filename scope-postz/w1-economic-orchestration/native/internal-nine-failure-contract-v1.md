# W1 internal nine: original boundaries and independent observations

This contract is written before the new adapter and its owning journeys.
Campaigns 0001 and 0002, including every failure and admission refusal, are
immutable. Registration, syntax checks and a successful helper exit are not
evidence that any of the nine families passed.

## Supported addition, not an invented universal research capability

The research addition is bounded, source-extractive primary research over
explicit original requirements and canonical tenant evidence. It is not a
financial-metric fan-out, web search, autonomous research agent, arbitrary
document interpreter or a new scheduler. Each requirement names a source and
an exact snapshot path. Outputs retain the exact original source/version/hash,
the question/requirement identities, missing branches and untrusted-data label.
The original requirement set, not the producer's returned list, owns completion.
Unavailable, oversized, changed and unauthorized evidence never counts as an
answered requirement. More than six requirements is unsupported, not truncated.

One source can satisfy several paths with one physical retrieval. Repeated
copies and alternate implementations are not independent confidence votes.
Different source-version identities establish distinct retrieval branches, not
statistical independence, truth or a calibrated error probability. Unknown
lineage and all monetary/supervisory costs remain explicit unknowns.

The adapter uses the existing tenant transaction, resource authority and
provider source-scope owners. Before returning any source bytes it rechecks the
original Work input, current authority, source permissions and source versions.
It is read-only: no Work, job, objective, effect, sandbox, model call, lease or
resource grant is created. Source text is never executable instructions.
Physical read concurrency is at most two, with explicit prerequisite barriers
and the original absolute deadline. A blocked prerequisite is not bypassed.
There is no hidden browser/network source or authority fallback.

  actual unit/attempt/event and revoked owner cut. No successful publication or

* **W011:** run the real dependent chain and an equipped native single-path

## Failure inventory and gates

### Sequential native floor, before its implementation

For an original maxParallel=1 exact-native execute/check chain, a current
fully observed two-stage fallback may already attain the supplied empirical
acceptance ceiling at the catalogue's minimum two native calls. When the
original S4 delay price is exactly zero and the native-call price is positive,
an extra paid CONTROL cannot improve that supplied finite objective. A small
bounded metadata check may retain that native path without compiling another
policy. This is an observed-model-relative dominance rule, not certainty of
future acceptance, causal inference, free supervisory CPU or economic gain.

Refuse this rule on missing, conflicting, failed, censored or UNKNOWN support;
non-current response pins/features; a positive delay price; parallel admission;
unexplained history; a partial/changed Work state; a non-native model; a different
method/checker; an unfinished original check; unaffordable publication; a chain
longer than two stages; or any unexplained resource consumption. No optimistic
probability estimate or alternate implementation vote may substitute for the
two actual original execute/check observations. Keep the prior physically
charged CONTROL journeys unchanged where this narrow rule is inapplicable.
The exact one-stage remainder of that same observed execute/check chain must
retain its one remaining native check as well. Recheck the actual completed
execute, exact conditional history and the same immutable fitted support; do
not suppress CONTROL at the root only to charge it between execute and check.
Any other non-root history remains outside this narrow rule.

Before isolated code, reject these possible failures explicitly: foreign or
missing source existence leaks; stale/revoked source bytes; Work-input drift;
source text requesting activation; source/currentness TOCTOU; cycles/unknown
prerequisites; path/prototype traversal; duplicate requirements; silent source,
byte, state or concurrency truncation; hidden activation; branch-error success;
partial bytes counted as complete; deadline reset on continuation; leaked
connections/children/locks; test process exit zero with failed/missing cases;
oracle importing the production selection/extraction logic; missing physical
receipts; dropped queued/missed cases; mutable evidence overwritten on rerun.

The final extractive read uses the existing same-client tenant material fence,
not an independent cached authorizer, while checking the original Work, rights
and source versions. It must not hold that fence during parallel source reads.
Work intake must acquire that same fence before row/delta/idempotency locks.
The existing canonical source-version writers already serialize on their source
row FOR UPDATE. The final read must share-lock those exact rows in sorted order
before re-reading the latest versions; a reader-only advisory lock cannot
serialize a source writer that does not participate. Use a no-mutation
read/write transaction for those row locks, not READ ONLY, which PostgreSQL
rejects for FOR SHARE. Do not add a late global material-fence acquisition to
the memory append seam: existing capital transactions hold S5 first, so that
would invert W1's material-before-S5 order. Preserve those existing writers.
The single-path metadata rule must reconstruct its immutable continuation
reference and original histories, reject non-controlled or conflicting support,
preserve every untouched unit/check, and require positive supplied net utility.
It must not replace a better STOP with a paid computation. Its own validation
time is metered; failure to establish the rule retains the existing controller.

Controlled concurrency pauses may signal only a fixture-owned physical worker
returned by the original native queue launcher. Observe an actual committed
owner event before pausing, retain the original clocks during the pause, and
always resume/settle/close the owned child. A late or missed pause is a failed
case, not evidence for the intended boundary. No peer/personal process may be
signalled. Queue priority remains the original parent's priority, not a new
scheduler; all submitted, cancelled, expired and outstanding Works stay in the
population and conservation oracle.
The pressure fixture may explicitly configure its original queue lease and
aging interval before any claim. It must retain those original clocks thereafter.
A second owned real worker must actually encounter the occupied native permit,
retain a durable capacity-deferred delivery without a physical debit, and later
record the original deadline miss. A queued row alone is not contention proof.
An aging number on a classless queue is not aging execution: the legacy claim
query ignores that number. Configure the original INTERACTIVE workload class
before either pressure worker starts, retain its canonical claim SQL identity,
and require that actual class in the independent fairness oracle.
The standing fixture must receive a validated original company context and an
explicit query/wait-capable governed worker before its first iteration. A
deal-free context error or ineligible worker is a failure, not an event wake.
Every owned closer has a finite bound, all remaining closers still run after
one fails, and no result may retain PASS when its finalizers failed. Idempotent
SUBMIT replay must recheck current owners on the same fenced accepting client.
Replay must not acquire an existing P2 row while holding S5: an actual worker
can already hold that row while waiting for S5. Reuse the same-client owner
assertion without appending another ACCEPTED/SUBMIT event or changing the
existing search. Only first acceptance records its boundary event. Original
idempotency, grant, parent and physical liability identities remain unchanged.

Each journey retains inputs, steps, actual observations, independent acceptance
and rerun command. A verifier must require all nine exact identities and every
W007/W014 subcase, plus child exit zero and no source/runtime drift. Internal
coverage stays NOT_RUN or FAIL until those observations actually exist.
Scope-development verification is separate from DOMAIN_QUALIFIED, ADMITTED,
PRODUCTION_ACTIVE, FIELD_VALIDATED, economic/comparator and protected gates.

## Disposable PostgreSQL ownership and interruption (outage correction)

The coordinator found roughly 2.8 GB of leaked C1/D2/R1/recovery scratch after
the provider outage. Normal-path `stop()` is insufficient: initialization,
migration, assertion, artifact writing, a deadline, SIGTERM, SIGINT and a failed
connection close can all bypass it. The embedded package also hangs if `stop()`
is called after its child has already exited, and does not delete an unstarted
cluster or its enclosing scratch directory. Persistent recovery data is not an
evidence-retention policy; retain the actual observations, not disposable PG.

Before initializing, every active W1 database owner must register its exact
new temporary directory, canonical database path and filesystem identity.
Normal and exceptional finalizers must attempt every closer independently,
stop only that registered cluster and remove the entire registered scratch.
An idempotent synchronous exit/signal fallback must cover forced process exit,
without waiting for another asynchronous database callback. Never delete a
directory with live/open owners, follow a replaced ownership marker, signal a
peer, or treat a cleanup failure as a retained PASS.

The outer resource wrapper must give each admitted child a unique temporary
namespace and, after termination/reaping, perform a separately bounded cleanup
of that namespace. It must verify exact descendant PG paths and current UID
before stopping a residual cluster; this covers a hard-killed inner owner or
nested session. Business and admission deadlines, the original 1200-second
admission window, load <=4.0, disk floor and all oracles remain unchanged.
Retain exact cleanup outcomes, remaining paths/open processes and nonzero
termination; do not hide failed teardown behind successful story observations.
Verification must include real fresh embedded PG success, setup failure and
timeout/interruption paths, not just a mocked filesystem or a zero helper exit.
Outer parents must give the resource wrapper its bounded teardown interval
before escalation; killing it after five seconds can strand the very locks
and PG namespace it is still cleaning. Repeated termination signals cannot
interrupt finalizers or restoration of a temporarily broken recovery source.

The first real lifecycle run (`resume-preparation-0002/cleanup-0001`) removed all
seven owned namespaces but failed because embedded-postgres' beforeExit hook
changed both deliberate exit-code-17 failures into exit 0. Preserve that failed
run, protect the selected nonzero owner exit at the synchronous beforeExit
boundary, and require a separately receipted fresh lifecycle run. A P2 result
cannot become PASS_LOCAL before every owned finalizer and scratch removal has
completed. The indirectly used P5 native fixture is part of this cleanup scope:
register before port/init, close every worker/pool/admin even if one fails, and
remove its enclosing scratch on both failed setup and ordinary close.
