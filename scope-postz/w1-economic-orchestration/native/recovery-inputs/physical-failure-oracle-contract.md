Registered before writing the v2 driver, oracle, or production after-file.
Extends, never replaces, `scope-postz/w1-economic-orchestration/native/physical-recovery-contract.md`.
Validation of this proposal is **NOT_RUN**. No runtime qualification is implied.

## Installation and frozen epochs

1. Parent installs only the proposed new scripts. Keep the production API at its
   recorded preimage. Freeze every production package and test dependency for
   the complete baseline process. Run both cases and retain its first failure,
   raw observations, process logs, and oracle receipt.
2. Parent reviews and installs the one-file production repair only after the
   baseline oracle identifies `PLAN_QUALIFIED_PRE_ADMISSION_STUCK`. Stop all old
   runtimes first. Freeze a new source identity, use fresh disposable fixtures,
   and run both cases again, supplying the immutable baseline observation file.
3. No production edit, import-cache reset, source swapping, or deadline
   extension within either runtime. `currentCodeIdentity` is checked before and
   after each case. A changed dependency is a failed run, not an excuse to
   reinterpret its evidence.

Use runner-supplied absolute Node, tsx loader, and Python paths. The runner must
provide loopback-only, already-migrated, explicitly disposable database URLs for
the existing administrator, finnor_app, and finnor_worker roles. This driver
does not migrate, create/alter roles, grant permissions, or create a signer.
It reuses the existing `nativeHttpFixture` signed-bearer fixture. Ordinary
S4/S5 fixture budgets are the original Work's budgets, never recovery top-ups.
No credential, bearer token, database URL, or signer material is evidence.

## A: claimed before physical admission

use the existing bypass1 helper, but submission, reads, and recovery are actual
signed-bearer calls with bypass0. Anonymous must return401 and a distinct,
same-tenant principal must receive404. Insert that identity before owner rights
are pinned. No fitting, fabricated capsule, private policy, or response oracle.

A real P1/P4-only restricted worker prepares original sources and selects the
original fallback without claiming P2. Stop this staging process. Save the
QUEUED EXECUTE_P1 unit, its actual admission count, selection event, exact
plan-qualified job key/payload, original acceptance, source rows, grant, Work,
episode, and absolute300-second deadline.

In a separate database transaction hold the existing advisory owner lock:
`pg_advisory_xact_lock(hashtextextended('s5-portfolio:' || tenantId,0))`.
Start a separate restricted production worker registered for P2. Observe its
durable running claim/delivery and its actual backend waiting on that holder.
At this cut the original unit is QUEUED and there are zero physical attempts,
not merely zero completed attempts. SIGKILL only that owned child PID; await
its OS exit with signal SIGKILL before releasing the owner lock.

Save the killed cut. Wait by the original database lease clock, with no job or
business-row mutation. A different restricted PID invokes canonical queue
recovery, which must quarantine this reconcilable delivery and preserve its
delivery outcome as `reconciliation_required` / `lease_expired`. Use the real
authenticated reconcile operation, save the immediate after-cut, then drive
only ordinary due jobs.

Baseline failure is specifically: the plan-qualified original delivery is
quarantined, no physical attempt ever existed for that delivery, reconcile
returns200, the original unit stays QUEUED, and no pre-admission recovery event
exists. Earlier failures, schema refusals, lock timeouts, or a different stuck
job do not count as the registered first failure.

After repair the exact failed delivery has the truthful no-admission
disposition/event. Its unit fails and its dependent verifier is not bypassed.
A different compatible module is really admitted, executed, independently
checked by PostgreSQL, and published through P1. The original P1 must become
TESTED with Fraction-recomputed43 and7/2. No grant/episode/candidate counter is
refunded or renewed; no replay of the failed delivery; no synthetic success.

## B: real durable SUBMITTED, possible physical execution

Use a separate original no-fit Work and budget. After P1/P4 preparation, hold
`LOCK TABLE finnor_os.p1_events IN SHARE MODE` in a separate transaction in this
dedicated disposable database. This observational lock does not edit business
rows. It permits SELECTs and all P2 admission writes but blocks the real
EXECUTE_P1 isolated-execution trace INSERT, which occurs after durable
SUBMITTED. Do not hold the S5 portfolio lock in this case.

Observe simultaneously: an original SUBMITTED attempt with admission debit,
RUNNING unit and job, and the victim's backend blocked by this holder on the
P1-events INSERT. Earlier admission/owner contention is not this cut. Kill the
exact owned PID and await SIGKILL exit, then release the table lock.
The outcome is deliberately MAY_HAVE_EXECUTED, not proved absent, even if
the child completed before its trace could be committed.

Natural queue lease expiry, canonical recovery, and signed reconcile must
yield UNKNOWN with identical original attempt/delivery/job/unit/effect
identity, grant debit, episode debit, and outstanding exposure. Signed resume
must not dispatch an alternative or replay the attempt. Signed cancellation
may advance its canonical generation, but cannot settle, refund, delete,
replace, or complete UNKNOWN. A later resume is refused. Tick the replacement
worker and reconcile again after the original physical leases expire
naturally; UNKNOWN and debit must still remain. No owner/provider receipt is
invented and no business effect is requested.

## Independent evidence and bounded costs

The collector retains raw original SQL rows at selection, contention, kill,
queue recovery, reconcile, and terminal/control cuts, plus SQL clock/locks,
actual child IPC/exit receipts, exact handler registrations, root resource
observations, cold-launch time, and original source/acceptance rows.
The separate Python oracle imports no production selection/checker or driver
implementation. It binds the cuts by original identity, checks exact equality
of keys constructed from actual admission count and original payload, checks
all counters/maxima/deadlines/grant/leases, and evaluates the original
acceptance expressions with Fraction over raw metric observation rows.

Each case has a120-second observer bound; the outer Python runner has a
300-second total bound including both cases, cleanup, and oracle. The original
business deadline remains300 seconds. Waits use real clocks, never UPDATEs.
Cost fields retain actual measured overlapping root intervals separately;
complete descendant CPU/memory and billing remain UNKNOWN/null. The killed
delivery, setup, contention, observer, and replacement-process engineering
work stay in evidence, never represented as free or added twice.

The existing native-oracle.py stays byte-for-byte unchanged. Its positive
CONTROL_W1/capsule-consumption predicates do not apply to these no-fit cases,
so it is explicitly NOT_APPLICABLE here, not silently weakened or reported
as passed. The parent must separately run that unchanged oracle on an actual
positive capsule-consumption fixture before broader native qualification.

Production repair boundary: only compute-search/api.ts; exact protocol,
tenant/payload tenant, principal, search, generation, unit, actual admission
count, and exact payload-derived W1 plan key; no LIKE or suffix wildcards.
Keep protocol1/2 behavior and every no-attempt/outstanding/live-delivery and

outside this proposal. Any failure there is retained and blocks qualification.
