# Portable compensation owner comparison

This records the execution contract before adding the portable supervisor. It
reuses the existing actual closing-owner case and its four original controls.
It adds no isolated unit tests and changes no acceptance assertion or deadline.

The baseline must reach an independently closed financial owner, while the
original W2 compensation observation remains OPEN. Only the specific missing
receipt-join assertion is an expected baseline failure. A startup failure,
timeout, missing observation, resource stop, or unrelated assertion is a failed
comparison. The repaired exact, wrong-amount, wrong-payee, and wrong-receipt
episodes must each pass the unchanged owner driver, including its physical
worker recovery and historical-capacity assertions.

Reverse only the two exact compensation adapter hunks in the allocation owner,
preserving all integrated W1 behavior. The other three production preimages
must match their registered repaired hashes before reversal. The new join module
is absent in the baseline. Retain all five before/after hashes and restore every
byte in a finally block. Unrelated tracked source drift invalidates the run.

Each episode retains the original 1,200-second bound, 4 GiB initial available
memory requirement, and 1.5 GiB disk floor. The supervisor requires 4 GiB initial
free disk and observes the disk floor throughout execution. It owns only its
child process family and its exclusive temporary PostgreSQL directory. Cleanup
must verify identities and fail if any owned database survives.

Hosted execution uses no production credentials, paid model calls, real actors,
or payment rail. The existing fixture makes disposable signing roots inside
its private temporary directory. Retain only the controlled original obligation,
controlled receiving-owner readback, driver results, and supervisor receipt as
shareable evidence. Never upload temporary credentials, full databases, or the
raw private runtime directory. These results prove the specific software join;
they confer no protected qualification, admission, field, or economic result.

The first Linux comparison stops at `CLOSING_OWNER_BOUNDARY_UNAVAILABLE` before
the receiving-join assertion. On this failure, retain the existing closing
owner's redacted diagnostic code, error class and stack frames from its actual
canonical event. Do not upload the full canonical snapshot: it includes raw
queue claim credentials. Missing later success artifacts must not hide the
earlier owner failure or be counted as the intended baseline regression.

The full repaired exact episode runs first in CI. Its success releases the
original missing-join baseline and three adverse controls in parallel. All five
episodes remain mandatory; a skipped control is incomplete verification. This
keeps a common setup/owner failure from launching four redundant failing runs.
