# Native integration, specified before owner implementation

## Whole-system shape

An event-only dispatcher is insufficient: a legal-looking offer can omit a leaf, overbook another Work, or lose a possible effect. The selected shape is a whole-graph, constraint-guided compiler and separately resolved checker, followed by recipient-authenticated, append-only contract events. The existing Work owns the original outcome. Existing authority, S1 source versions, S5 portfolio lock/reservations/consumptions, S6 executor/dispatch observations, S7 records and S8 non-admitted experience keep their respective meanings. W2 does not create an alternative identity directory, resource ledger, queue, or effect broker.

The native API accepts canonical original Work/source/resource references, not a caller-signed checker result. It resolves originals again at compile, acceptance, disclosure, execution, verification, cancellation and recovery. Operational return edges may be reciprocal; budget ancestry may not be.

## Canonical resource representation

One original W2 root reservation is a typed S5 specialization using the existing `s5_proposals`, `s5_reservation_origins`, `s5_reservations`, `s5_consumptions`, `s5_consumption_states` and history. The exact existing canonical resource-path checker checks resources, retained commitments, every period and coupled covenants. All mutations use `s5-portfolio:<tenant>`. This does not forge an X1 mandate.

128 actor schedule agreements and 512 assignments do not mean 128 S5 resources or 512 independent S5 grants. A complete original resource schedule funds the root; the W2 graph carves its active frontier. Accepted per-person time windows across Works are checked under the same portfolio lock. Each physical attempt gets one immutable original consumption identity before dispatch. Unknown attempts retain their ceiling and do not authorize replay. The existing immutable envelope is retained conservatively after observed spending; an estimate of newly free capacity is not silently released.

## Trust and execution

Ordinary API authentication uses actual bearer verification with bypass disabled. Internal assignment and voluntary recipient acceptance are different dispositions and bind exact immutable terms. Current canonical actor classification, authority, evidence and availability are required. External identities must resolve to canonical external records and an authenticated binding; unsupported identity channels fail closed, not as fictitious employees.

Disposable deterministic computation uses the existing isolated S6 executor, with untrusted output, independent original-criterion verification, no inherited credentials, and no network/effect authority. Consequential operations must use an already lawful exact S6 origin. The existing protected `DELEGATED_CHILD` refusal is not removed. Unsupported protected/resource classes remain refused.

## Finite native proof

Before expensive runs, freeze driver inputs, cases, limits, source identities and literal expected observations. Maximum runtime is 20 minutes per native run, 1 worker, 1 embedded database, no simultaneous full builds, minimum 2 GiB free disk, API/worker heap at most 1536 MiB each. Keep private artifacts and do not record credentials.

1. Ordinary authenticated Work receives the original graph. Compile through a physically claimed registered job; check a separately resolved canonical graph. Observe exact recipient disposition, native S5 intent, real S6 computation, S1 evidence, independent verification and mounted readback.
2. Challenge wrong recipient, changed terms, expired/revoked capability, concurrent same-person windows, cross-tenant/principal read, omitted live leaf, resource duplication, unknown-effect reassignment and false parent closure at their owning consumers.
3. Kill a test-owned worker with SIGKILL after durable acceptance/intention. Restart with the original job/root/grant/deadline. Compare actual claim fences, S5 intent identity, possible-effect history and executor attempt counts.
4. Exercise all profile dimensions together (128 actors, 512 live records, depth eight), plus explicit excess rejection. Builder development evidence is not protected structural qualification.
5. Build the final API/worker/UI paths, repeat the owning chain on those bytes, and reconstruct separately from sealed source, locked dependencies and documented assets. Do not label an unrun reconstruction as passing.

Genuine human acceptance and judgment require an actually consenting authorized person. Controlled service actors are identified as controlled service actors. Human, protected custody/admission, field activation, completed-Z comparison and economics are separate gates.

## Implemented participant and experience channels

Recipient actions bind the real authenticated principal, current canonical actor/authority, current programme revision and exact terms. A separate checker sees only the delivered value and immutable criterion needed for their review, not the parent graph. Terms revisions cannot widen the original envelope and always require fresh acceptance. Replacement is limited to an undispatched leaf with no descendants or possible effect; its unused carve is explicitly released under the original S5 reservation before the actual backup is offered work.

S8 reconstructs non-admitted experience from committed Work/assignment/delivery/verification and actual S5/S7 records, then retains it through S1 source versions. Observed capability/availability, accepted-obligation history, unknown resource exposure and source class remain explicit. This record grants no qualification, training rights, causal reward or personality judgment.

## Reproduction commands

Run from the isolated repository, using its locked Node 22 dependencies:

```sh
cd finnor-os
node_modules/.bin/tsx scripts/postz-w2/run-domain-e2e.mts
node_modules/.bin/tsx scripts/postz-w2/run-native-e2e.mts
node scripts/postz-w2/build-development.mjs --output /absolute/new/w2-backend
cd ..
node scripts/postz-w2/build-frontend.mjs --output /absolute/new/w2-frontend --origin http://127.0.0.1:49187
```

Builds require committed clean source, use distinct W2 manifests and never activate production. For the final installed/browser run, set `FINNOR_W2_INSTALLATION`, `FINNOR_W2_FRONTEND_INSTALLATION`, `FINNOR_W2_MOUNTED=1`, and the exact compiled `FINNOR_W2_FRONTEND_ORIGIN`. The native driver emits the path to a mode-0600 disposable fixture outside the workspace. `scripts/postz-w2/browser.mjs` uses that file without recording credentials. Actual DOM assertions, screenshots and native rows are retained separately. The browser client must use the assigned desktop CDP session, never a hidden substitute or fake acceptance callback.
