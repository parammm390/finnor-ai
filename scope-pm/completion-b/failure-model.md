# Registered failures before implementation

Every story retains inputs, source/runtime cut, expected contract, raw results,
timestamps, exclusions and rerun command. A negative counts only at its intended
guard. These are development engineering stories, not sealed S8 qualification.

## P3

1. Checkpoint contains plaintext private state; tampered AAD/ciphertext/tag,
   wrong tenant/Work/root/rights/module/image/input/scenario/grant/attempt or key
   succeeds. Key version changes are mistaken for a compatible checkpoint.
2. Revoked/expired checkpoint can be served, cloned or recovered; erasure deletes
   immutable attempt/S6 history or makes an outstanding charge disappear.
3. Crash during resource acquisition/preparation/launch/publication/release loses
   ownership, scratch path, descendant or lease. Cleanup's `finally` is assumed
   to have run. Recovered unknown physical usage is incorrectly priced at zero.
4. Acquisition/SQL/body/stream/verification consumes a fresh timeout; publication
   happens after the original clock. Cancellation fails to kill/query-cancel or
   refunds submitted work. Cleanup retries accidentally execute business work.
5. Concurrent roots/Work evade aggregate cgroup memory/CPU/PIDs/disk/concurrency;
   logical slots or sampled RSS are falsely called physical confinement.
6. P1 ref parser/fixture/native alias supplies a HarnessProgram without a real
   current owner reader. Generated code receives DB credentials or network.
7. Warm image includes private identities, stale rights or altered bytes.
8. All original physical publication/crash, fixture autosave/navigation and
   replay/reuse comparisons retain their original denominators.
9. Queue waiting or a restored descendant obtains a fresh episode deadline.
   A checked result blob is published after the accepted ancestor clock.
   A disposable independent timestamp advance tests this without waiting or
   modifying production authority. Request timestamps remain immutable for
   the application role.
10. A valid sealed restore fails only when the ordinary SQL deadline reader
    traverses a real checkpoint ancestor (PL/pgSQL local/column collision).
    The original H-I restore owns state/identity correctness; the episode story
    owns unchanged accepted time across successive restore generations.
    Full-suite crash/retry scheduling must name the intended disposable job,
    preserve other jobs' eligibility, and record the actual delivery fence.
    Selecting a test job never adds a production claim or queue bypass.
