## Eight original steps

The original wording is preserved here and in `phase-plan.md`; delivery05's full expansion is in `governing-registration/delivery05-eight-steps.md`.

1. Define a typed programme grammar from admitted S3 interventions/native financial operations, S2 inquiries, S4 control constructors and S5 resource requests. Supported terms include only their implemented validity domains.
2. Generate candidate programme structures and term parameters. A candidate may stage a commitment, propose a milestone condition, change an offer, seek information, wait or stop. Economically different conditions count as different alternatives; rewritten prose does not.
3. Bind every programme node to owner references, source/estimate dependencies, units, required observations, cost, deadline and failure behavior. Pure calculations run natively where supported.
4. Refine an abstract subproblem into a smaller executable method when its implementation is missing. Type-check and test generated modules in isolated cells before dependent use. Bound recursion, steps and resources.
5. Evaluate candidates under the declared joint S3 model family and S5 resource coupling. Compare information and action sequences together using S4 semantics, including delayed observations and adaptive counterparties.
6. Ask M1 for newly introduced evidence demands and M4 for challenge searches. M2 allocates the granted computation; it does not change the objective or risk tolerance.
7. Mutate/refine term values and programme structure. Reuse valid subcomputations with complete dependency keys. Never reuse a real effect attempt as a replayable search branch.
8. Submit a candidate implementation to S4/S5. Report exact/reference/model-relative certificates and unresolved search gaps. New counterparty terms remain proposed until actual agreement is evidenced.
