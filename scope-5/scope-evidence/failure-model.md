Credible failures, covered at the strongest actual owner boundary:

1. Resources: stale/foreign revision; wrong entity/currency/unit; hidden stock vs
   flow/occupancy semantics; unknown availability; future knowledge; uncertain
   proceeds; missing maintenance/recovery/terminal demand; revoked rights.
2. Model: standalone values silently added; omitted complementarity/substitution
   or concentration covenant; independent re-pairing of common shock paths;
   scenario/node path uses private/future information; omitted reachable branch;
   policy/demand identity changes under a retained identifier; false probability.
3. Clearing: omitted canonical constraint in backend matrix; numerical small
   coefficient disappearance; float rounding accepts resource breach; infeasible
   existing obligations concealed by empty allocation; timeout/failed solver
   reported as optimal; bogus bound below a demonstrably feasible programme.
4. Commitment: two processes race insufficient persisted capacity; stale solution
   commits after revision; partial acquisition survives transaction abort; retry
   changes semantic payload; resource/covenant updates skip active commitments;
   restart loses ownership; certificate expiry silently releases exposure.
5. Consumption/recovery: forged/foreign S6 ref; duplicate node consumption;
   incompatible branches consumed; crash after intent before acknowledgement;
   unknown provider outcome releases resources; cancelled policy mistaken for
   cancelled external effect; settlement loses cumulative spent cash or terminal
   liabilities; duplicate release; correction rewrites prior responsible history.
6. Authority/integration: client fabricates resolved certificate; ordinary
   persistence mistaken for protected append; branch bypasses current resource,
   source/right/model checks; handoff claims execution authority; tenant/principal
   crossing; role suspension after solving; resource revision between recheck and
   commit; unbound provider/effect target accepted.
7. Operation: unbounded scenario/node expansion, child solver hang/oversized
   output, process recovery overhead omitted from timing/cost, post-result
   benchmark changes, numerical estimates relabeled proof, synthetic H1 value
   booked as H2 economic benefit or system frontier dominance.

Failure handling is conservative: no hard constraint relaxation; no implicit
safe WAIT; unresolved effects remain accountable; existing breaches report
reconciliation/re-clearing need. Prepared event records and ordinary database
history are explicitly unprotected. Exact small-domain feasibility/objectives
are model-relative; forecasts, causal identification and enterprise truth remain
their upstream qualifications. Protected S6/S8 releases cannot be synthesized.
