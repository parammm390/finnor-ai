# Recovery and execution boundaries, before native-driver implementation

The earlier failure map already requires physical claim, checked-artifact and
ambiguity cuts. The driver must make them physical process-group exits, not
exceptions or queue/DB mutations. Pause only a recorded independently supervised
owned worker group, observe the durable boundary while stopped, kill that exact
group, prove exit, restart the same entry/source/build with explicitly named
environment variables, and compare original IDs, fences, remaining capacity and
UNKNOWN. A cascading launcher, borrowed PID, changed process start time, missing
actual boundary, or changed artifact is a failed/blocked cut, never a pass.

Two owner-use recovery defects were found by source inspection: a crash between
native action insert and the use receipt, and replacement materialization on
redelivery of an already-bound draft. The fix uses the existing trusted
`onActionPersisted` callback before possible native execution. Redelivery reads
the actual action's immutable argument references, revalidates the accepted
model/profile/source/claim, and records use idempotently only after those checks.
It does not recompute or charge a new materialization for the same canonical
argument. Original native authorization still owns actual business dispatch.

The executable driver must reject without authority before importing pg,
Playwright or native owners. It must not provision, migrate, seed, grant, forge
Auth/context, edit a queue, supply SQL or accept arbitrary shell commands.
Original query observation uses the actual API `requireContext` against a real
bearer, then the existing orchestrator query owner, because the public query
endpoint intentionally retires harness/confidential owner queries. Real mounted
login and HTTP/DB observations are separate required checks.

The oracle is committed independently before acquisition and contains original
standing inputs and complete expected native rows plus a literal canonical
inventory denominator. It cannot be generated by the candidate model or registry.
All positive, negative, four-stage currentness, mounted reload, shared S5/S6/S7,
three recovery cuts, and separate installed repetition must be selected from a
closed case map. Missing fixtures or authority remain NOT_DELIVERED / NOT_RUN.
Only synthetic disposable data is permitted. Credentials stay in process memory;
receipts retain hashes, IDs, environment names and sanitized observations.

Packaging failures remain evidence: Next generates only the two distDir
declaration paths, unrelated engineering scripts are not production entrypoints,
and `node:sqlite` is a prefix-only builtin. Canonical subprocesses sanitize their
environment, so installation must rewrite actual TS-loader invocation operands
to the fixed emitted loader rather than rely on inherited NODE_OPTIONS.
