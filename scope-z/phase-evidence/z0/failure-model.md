# Z0 failure model before product changes

This is coordinator-local preparation, not a dedicated Z0 execution launch or
Z0 completion. No new authority, admission, real provider effect or publication
is authorized. The full locked PRD remains binding.

## Native query observation and identity

Credible failures:

1. A semantic Work ID is stripped as envelope metadata.
2. A native-only intent is accidentally added to the public OpenAPI/planner wire.
3. A parser-only change appends a new Work input and invalidates the original
   programme/computation.
4. A read marks the underlying material business goal complete.
5. An envelope Work and semantic Work diverge; another tenant, principal,
   inactive user or insufficient role gains read access.
6. The native original input, source/model/terms revision or required
   independently checked consumer is stale.
7. Query accounting starts before native authorization/currentness checks.
8. An idempotent read returns stale/private output or causes a second mutation.
9. Refusal after entering a schema, DB or final guard is mistaken for the required
   supported positive native owner path.
10. A development auth bypass, mocked orchestrator/reader or controlled auth
    provider is mislabelled real production authentication.

Planned observations: actual typed parser/native dispatcher; original Work,
work_inputs, programme/computation revision and query-accounting rows before/
after; independently specified principal/tenant/revision denials; original
consumer result; immutable source/build/runtime receipts. Keep public OpenAPI
native exclusions. See `orchestration/z0-native-query-source-clarification.md`.

Do not implement a public parser-only restoration. First prove the intended
native observation path and the no-steering-input invariant. If a public refusal
is intentional, record a non-defect, not an exposure repair.

## Canonical capability reachability

Credible failures:

1. A generator parses only easy string literals and omits real canonical entries.
2. A generated file and coverage audit agree with the same incomplete list.
3. Required references differ from the canonical runtime source.
4. Wait/check/read/action kinds collapse into misleading mutation capabilities.
5. A human-only, unavailable or native non-model-proposable entry becomes a model
   action; especially economic-right transition effects.
6. A new independently maintained “canonical” list merely hardcodes today's six
   omissions.
7. Generation requires provider credentials, sends a network/business request or
   executes a plugin merely to enumerate its registration.
8. Native internal query availability becomes a public HTTP route.
9. A future canonical entry or metadata change silently disappears.
10. A mutation/control is removed only from a local expected list rather than
    rejected against the actual complete source.

Planned finite checks: derive the real canonical runtime manifest without
executing actions; compare exact identity and metadata sets; deliberately remove
an entry, alter required context/proposability/kind and reject; preserve deliberate
native/human/unavailable dispositions; regenerate/check the actual product
manifest and coverage; verify affected mounted consumers from the final build.

## Runtime/packaging and verification honesty

- Run required Node 22, actual locked dependencies and installed Next docs.
- Do not treat clean npm installation as emitted/installed application proof.
- Verify real queues/fences/checkers/owners, currentness and S6 identity before
  declaring the complete phase, not just a generated JSON or source probe.
- A physically interrupted worker and ambiguous controlled effect retain the
  same original obligation/UNKNOWN and remaining budget.
- Browser/session/principal switching must not resurrect private stale state.
- All finite runs retain original inputs, steps, exit codes, observations,
  source/build identity, failures, costs/gaps and repeatable reconstruction.
- Missing internal adapters, native assets, meters and UI remain incomplete
  engineering. Protected custody/comparator/field outcomes remain separate.

No post-code unit tests will be introduced. Use failure-first real E2E where
available; label narrower source/runtime probes exactly.
