# Z5 native integrated run: failure model (written before the session script)

Scope: running `finnor-os/scripts/project-z/z5/native-e2e.mjs` on the integrated candidate (request 07 applied, e481133) against an ordinary disposable native stack (embedded PostgreSQL 55441, real pinned Auth 54321, API 3101, frontend 3001, runner `--no-worker`). This note lists how the run can be faked or can fail and the independent expected outcome. Expected outcomes are written from the PRD/owner contracts and the DB, never from the producer's own output.

Coverage limits carried into every report: sound-subset context, finite-path nonblocking, exact-listed-kernel correspondence, 84 distinct inputs (not 256 fresh), LOCAL FILE journal recovery is not native queue/S5 recovery. No acceptance, protected admission, 100x or activation is claimed.

## Decision: the `s8` owned process
Z5 calls the ORIGINAL S8 lifecycle (`packages/capability-evolution/src/server.mts`) over loopback HTTP (`native-s8.ts` -> `POST /command` `Z5_COMPOSITION_ADMIT|CURRENT`) and reads S8/S4/S5/S6 references through the S6 ledger (`readOwnerTransportReference`). S8 is therefore a real separate process, so the driver's `ownedProcesses.s8` guard (pid, port, source head, cwd under repo, same uid, listening socket inode owned by that pid) is correct and is NOT relaxed. The session must start the real lifecycle process (plus the real S6 ledger it commits to) and identify the pid that actually owns the listener from /proc. A guard relaxation was rejected: it would let a missing S8 pass.

## Failure/fake cases

| # | Way to fake or fail | Independent expected outcome |
|---|---|---|
| F1 | Fake s8 pid (any live pid, the driver itself, the shell) | Guard rejects: the pid's `/proc/<pid>/fd` has no socket inode in the LISTEN table for the declared port. Session writes only pids found by scanning `/proc/*/fd` against `/proc/net/tcp*` for the real port owner. |
| F2 | Borrowed listener (the s8/api/frontend entry points at the launcher parent or another worker's process) | Guard rejects on inode ownership or cwd outside repo; session resolves the actual owner pid of ports 3001/3101/S8 and refuses to start if the port was busy before it started the process. |
| F3 | Wrong DB role: worker child runs as `finnor_app` or driver pool as `finnor_worker` | Worker cannot claim jobs globally (RLS) -> request never leaves the queue; driver pool assert `current_user='finnor_app'` fails. Fix: worker child gets `FINNOR_WORKER_DATABASE_URL` (role `finnor_worker`), driver pool and API stay `finnor_app`; recorded `current_user` values are in evidence. |
| F4 | Stock worker also running (steals claims) | `--no-worker`; session asserts no `apps/worker` process before the run; claim attempts in `z5_link_attempts` must be exactly the driver-owned worker pids. |
| F5 | Authority file forged beyond the declared disposable scope (invented signer/grant/protected admission, wrong sourceHead, expired, non-loopback DB) | Authority contains only the operator declaration for this disposable stack; sourceHead equals `git rev-parse HEAD` of the remote worktree (committed tree, synced before run); guard failures stay failures. No signer/grant is invented. |
| F6 | Expected values taken from the producer (artifact digest, certificate, replacement from the worker output) | Driver asserts against durable rows read through RLS and the frozen/owner contracts (`z5_link_requests/episodes/attempts/events`, `compute_resource_leases`, queue rows); session never feeds producer output back as expectation. |
| F7 | Allowance reset after kill (attempts or quota restart at 0; fifth delivery succeeds) | Attempts stay 4 after three kills + final; fifth submit with new idempotency key -> 202 `INCOMPLETE`, `requestId:null`, `newAllowance:false`. |
| F8 | Lease shortened or stolen (row deleted/updated to skip waiting) | Next worker claims only after `native:z5-institution-linker` lease expires/is released by the owner path; driver reads lease through tenant RLS; session never writes the lease table. |
| F9 | Deadline renewal (original deadline moved on retry) | `originalDeadline` of request/episode/reservation unchanged across 4 attempts (driver compares to authority value). |
| F10 | Stale S6 callback treated as acknowledgement | Delayed original S6 callback after the AFTER_REPLACEMENT kill makes the request `STALE`, adds observation events not in the snapshot; stale `institution-link-use` refused (>=400); obligations retained; no consumption acknowledged. |
| F11 | Callback faked by direct DB write | Callback comes only from the real S6 dispatch/reconcile mechanism (ledger + broker + loopback TLS provider with lost response -> UNKNOWN, later reconcile). Session performs no inserts into S6 tables. If this cannot be arranged it is reported NOT_RUN with the exact gap. |
| F12 | Cancelled request consumed (admit/use/plan after cancel) | 4xx on each, durable-state digest identical before/after. |
| F13 | Cross-tenant read (second owner reads first tenant's request/Work) | 403/404; second tenant has `tenantId != identity.tenantId` (separate tenant row, separate Auth user) or the step FAILS as `second tenant not distinct`. |
| F14 | Second tenant not distinct (same tenant, second user) | `otherIdentity.tenantId == identity.tenantId` assertion fails the run; session creates a genuine second tenant via the product bootstrap path. |
| F15 | Private result survives sign-out / root switch (panel DOM or storage) | After UI sign-out and alternate Work/root switch, panel DOM has no first-Work artifact digest; reload shows only the permitted state. |
| F16 | S5/S6 obligation dropped by replacement/live-state bridge | `obligationRefs` identical in request, certificate and handoff after replacement; settlement/obligations remain after stale and cancel. |
| F17 | Credential in evidence (tokens, passwords, DB URLs, private keys) | Private files 0600 under state dir; evidence directory scanned for password/token/JWT/URL-credential patterns before export; commands never echo env. |
| F18 | Source changes while processes run (loadedBuild mismatch) | No source edit after sync until the run ends; each attempt syncs a committed tree and records HEAD. |
| F19 | Mixed run: stale processes or port reuse from a previous attempt | `native-run.sh` aborts exit 75 when ports are busy; every attempt has an immutable name; failed runs are kept. |
| F20 | Evidence directory escapes `scope-z/phase-evidence/z5` | `e2e-tools.mjs evidenceDirectory` realpath check; session writes to `<worktree>/scope-z/phase-evidence/z5/native-integrated-<name>` and copies sanitized artifacts to `FINNOR_NATIVE_EVIDENCE`. |
| F21 | Session fabricates upstream S3/S4/S5/S6 objects by direct SQL | Upstream objects go only through owner routes/libraries (S3 fit, S4 synthesize/handoff, S5 clear, S6 prepare with Work lineage). A step the owners refuse is a FAIL with the owner's refusal recorded, not patched around. |

## Expected observable per driver step (PASS only when independently observed)
login; pool role; contract register 200; submit 202 + conflicting preimage 409 `Z5_ORIGINAL_IDEMPOTENCY_CONFLICT`; kill AFTER_CLAIM; kill AFTER_CERTIFICATE; kill AFTER_REPLACEMENT; final worker -> `USED`, queue `completed`, 4 attempts; composition-plan 200 + `S4_ORIGINAL_COMPOSITION_PLAN_CONSUMED`; non-mutating reads; fifth delivery refused; mounted panel + alternate Work; second tenant denied; sign-out; delayed callback -> `STALE`; stale use refused; cancel; post-cancel refusals; revoke -> `REVOKED` visible after reload. ## Defects found while reading the integrated tree (entry written before each fix)

D4. `registerFixedProfile` requires `digest(profile) === sourceRef.contentDigest`, but the profile content schema itself contains `sourceRef`. The S6 ledger accepts a reference only when `sha256(canonical(content)) === reference.contentDigest` (`referencePreimageDigest`), so the content cannot contain a descriptor that holds its own digest (a hash fixed point). No ledger-published profile can ever register: `institution-contract-register` would refuse every real S8 reference with `Z5_PROFILE_CANONICAL_PREIMAGE_REQUIRED` or fail the schema.
 - Wrong fix (rejected): accept a caller-chosen digest or skip the digest check.
 - Independent expected outcome after the fix: content published to the real ledger WITHOUT `sourceRef` registers; content whose canonical digest differs from the descriptor digest, or content carrying an unknown `sourceRef` key, is refused (strict schema); the stored profile body is the verified content plus the descriptor that was read back from the ledger.
 - Fix location: `z5-institution-linker/owners.ts` (Z5 owned).

D5. (planned verification, not yet a defect) The launcher fixes the application environment at start while the S6 ledger / S8 lifecycle processes and signed configurations are created later by the scenario. The `z5` profile therefore only pre-creates launcher-owned root keys and deterministic private file paths; the transport policy and the S8 consumer policy are signed by the scenario with those roots after the processes exist. Expected failure if wrong: owners see `OWNER_TRANSPORT_PRIVATE_FILE_UNSAFE`/ENOENT on the first call; the scenario writes the transport file before any owner call that can read it.

D6. (planned verification) The scenario-owned stock worker used to build the X1 original parent must not run while the Z5 driver's exclusive worker runs (F4): it is stopped and its absence asserted (no `apps/worker`/`z0-worker` process) before the driver starts.

## Successor session: defects diagnosed from retained run w5-native-03 (entries written before their fixes)

D7. Z5N-04 `OWNER_TRANSPORT_PURPOSE_INVALID` (owner-transport.ts:56). The scenario ledger helper `z5-ledger.mts` declared a `CONSUMER` route for owner `S6` (`S6_READER`). The transport grammar accepts `purpose: CONSUMER` only for semantic owners `S7` and `S8` and refuses it with an `originSigner`; the S6 read path (`readOwnerTransportReference`, the `obligations/read-execution-handoff` route) uses the `OWNER` route (the default purpose). Every owner call that loads the policy therefore failed, including the S5 enqueue inside the X1 parent fixture.
 - Wrong fixes (rejected): widening the transport grammar to allow an S6 CONSUMER route; dropping the purpose check.
 - Independent expected outcome: the policy contains OWNER routes for S2/S5/S6/S7/S8 and CONSUMER routes only for S7/S8; the policy loads (the first S5 enqueue in Z5N-04 succeeds); no unused S6 read-only credential exists.
 - Fix location: `native/z5-ledger.mts` (scenario helper).

D8. Z5N-09 S8 boot `ZodError too_big sourcePins maximum 128`. Observed sizes from `z5-012-s8-pin-sizes.json`: S8 loaded closure 114, Z5 build files 34, union 137. Cause 1: `native-s8-owner.ts` requires EVERY Z5 build file to be pinned in the S8 lifecycle policy `sourcePins` (the exact phase source closure), and `assertCapabilitySourceClosure` requires all 114 S8 closure files, so the policy needs 137 pins. Cause 2 (product defect, outside Z5 ownership): `LifecyclePolicySchema` declares `sourcePins: PolicySchema.shape.sourcePins.max(256)` with the comment that the larger closure is intended for the scientific sibling; under the pinned zod 4.6.7 a second `.max()` on an array that already has `.max(128)` ADDS a check, so the effective cap stays 128 (observed: `z.array().min(1).max(128).max(256)` rejects 200 items, `z.array().min(1).max(256)` accepts them). The declared 256 cap is therefore inert for every consumer of the larger closure.
 - Wrong fixes (rejected): trimming the Z5 build file list or the S8 closure to fit 128 (weakens the exact source identity); skipping `assertCapabilitySourceClosure`; editing pins out of the policy.
 - Independent expected outcome: the lifecycle boots only when every pin is the real sha256 of the loaded file; policy with a tampered pin or a missing closure file still fails at boot.
 - Ownership: `packages/capability-evolution/src/lifecycle.ts` is not Z5-owned. Exact request patch is in the final report; the session is run with that patch applied only in the scratch remote worktree (clearly recorded) to expose the downstream defects.

D9. Z5N-06/07/08/11/12/14 cascade. Root cause is D7 (no parent from Z5N-04 -> no root, no chain, no obligation) plus a latent second cause in Z5N-07: it roots the S3/S4/S5 chain at the first active `external_organizations` row, i.e. the seeded phase-9 organization whose world is PARTIAL by design; the S3 fit gate requires canonical COMPLETE coverage (same defect as Z1 e5b2d1c). The chain must root at a FRESH organization whose world holds only fixture evidence (Z1 pattern).
 - Independent expected outcome: S3 fit returns FITTED, S5 clearing FEASIBLE, S4 handoff returns preparation/allocation/consumption refs; the obligation reads back with the original Work lineage from `s6_obligation_origins -> domain_actions.work_id`.

D10. Z5N-13 never implemented: the driver step `delayed-independent-callback-and-currentness` needs a REAL later independent S6 observation of the carried obligation (`obligations/read-execution-handoff` observations whose eventIds were absent at AFTER_REPLACEMENT) that makes the request STALE; it must come from the S6 dispatch/reconcile mechanism, never from a table write or the scenario calling a Z5 endpoint (F10, F11).
 - Expected outcome: dispatch of the obligation uses the governed-dispatch machinery with a loopback fake provider whose response is lost -> S6 UNKNOWN; a later independent reconcile/callback observation is appended by the S6 owner; Z5 reads it through the owner and marks the request STALE while obligations stay retained and UNKNOWN is not turned into success.

## Defects diagnosed from w5-native-04 (entries written before the fixes)

D11. Z5N-04 `OWNER_ORIGIN_RIGHTS_INVALID` (owner-transport.ts:90). After D7 the policy loads, but the X1 original-parent fixture stores S5 capacity resources whose `rightsRef` is `authority:<tenant>:<authority_states.revision>` (x1-origin-fixture.mts), while the scenario ledger accepted only `s5-owner-rights` for the S5 route and S5 ledger token. Every S5 owner delivery enqueue is checked against the route's `rightsRefs`, so the parent creation failed (cascade to Z5N-06/07/08/10-14; Z5N-09 itself PASSED, the S8 lifecycle booted with 137 pins once D8's patch was applied in the scratch tree).
 - Wrong fixes (rejected): weakening `verifyOwnerDeliveryOrigin` or accepting any `authority:*` string; re-labelling the fixture rights as `s5-owner-rights` (would make the S5 resources claim a rights reference that is not the authority revision they were issued under).
 - Independent expected outcome: the S5 route and S5 ledger token declare an explicit finite list of `authority:<tenant>:<n>` references (the authority revision at ledger creation plus a bounded window of 96), a reference outside the list is still refused (`OWNER_ORIGIN_RIGHTS_INVALID`); S2/S6/S7/S8 routes keep the single `s5-owner-rights`. The window is declared in the signed policy before use; no origin is accepted that the signed policy does not list.
 - Fix location: `native/z5-ledger.mts`, `native/z5-session.mjs` (scenario).
