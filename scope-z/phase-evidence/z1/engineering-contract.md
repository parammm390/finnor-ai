Each has its own original programme, output, parameters, source permissions,

## Two whole-shape alternatives, compared in this session

**A, indexed joint DAG:** hash-cons exact typed operators across nonidentical
original graphs inside the complete lawful partition. Retain reverse consumers
and source dependencies. A changed source/revision/parameter changes only its
dependent keys. Recompute dirty operators, reuse unchanged values, independently
recompute every original programme, and allocate each actual shared charge
equally to its sorted original consumers using exact rational ticks.
Advantages: actual joint execution and selective maintenance; explicit
projections, conservative invalidation and reproducible allocation.
Costs: discovery, retained values, checker recomputation and checkpoint storage.
Retractions use exact bag subtraction before recomputation, not unsafe
monotone-only delta propagation. No algebraic rewrite is admitted implicitly.

**B, independent evaluation with tuned per-Work caches/indexes:** execute each
original DAG independently, caching exact unchanged nodes only for that Work.
Use indexed equality joins, exact grouped aggregation and bounded selection.
Advantages: less discovery/metadata coupling on disjoint graphs, simple
per-Work recovery; strong eligible direct fallback. Costs: repeated common
transforms, retained independent indexes, the same checking and native floors.
It does not itself supply a jointly executable multi-Work refinement object.

**Decision:** implement A with the same indexed operators available in B.
Expose B as a diagnostic execution mode, not a defeated qualified X/Y release.
Dirty-node full recomputation is declared and charged. No differential-join
rewrite, cost superiority, novelty or 100× claim follows. Low overlap must
remain a useful exact result even if discovery makes A more expensive.

## Supported semantics and expected values

Finite pure typed DAGs: source, filter, expression projection, equality join,
bag/set union, grouped exact sums and deterministic bounded selection. Rational
tokens are signed integer or numerator/positive-denominator text; no binary
floating conversion. Exact integer/rational types carry units and currency.
Addition, comparisons and union require matching types/units; multiplication
requires a dimensionless operand; division preserves or cancels declared units.
Rounding is explicit (half-even, half-away-from-zero, floor, ceiling, truncation).
Set projection collapses duplicates; bag projection retains them. Global empty
sum is the declared typed zero; keyed empty sum has no groups. Selection ties
use the full canonical row, retaining bag multiplicity, never input arrival.

Maximum 1,000 original Works, 4,096 original operator nodes per batch, 100,000
source rows, 1,000,000 materialized derived rows and 512-bit reduced rational
components. At least two original Works; withdrawal may leave fewer active
Works without deleting their history. Additional explicit byte/operation/time
limits may return INCOMPLETE. Unsupported operators/types/effects never
silently change semantics. All original nodes must be reachable and covered.

The independent executable checker uses Python's Fraction and an original
per-Work interpreter. It receives original input separately, never evaluates
the shared producer DAG, and compares full schema, multiplicity, ordering and
per-Work dependency bindings. Its identity and exact candidate/request digests
are retained. This is implementation diversity and public development
recomputation, not independent protected governance.

## Failures and required observations

1. Missing/duplicate Work/node/source, cycles, hidden unreachable nodes, unknown
   fields/operators, floats, unit/currency changes or noncanonical numeric
   overflow: reject, with no usable exact output.
2. Duplicate-key/self/cyclic joins, empty groups, set-vs-bag collapse, rounding
   signs and selection ties: compare every original output independently.
3. Row insertion and signed retraction are atomic; missing retractions cannot
   underflow a bag. Changed source/programme/threshold/topology invalidates its
   dependents; unrelated values remain reusable.
4. Cross-tenant/principal/private/permitted-use/revision/classification access:
   no reuse or metadata/output disclosure. Errors contain codes, not raw data.
5. Source revocation suppresses affected results, not unaffected results.
   Withdrawal retains original provenance, costs and all unresolved obligations.
6. Source/rights/model/terms/objective/units/code/checker drift at claim, check,
   publication, use and effect: stale/revoked, never current on an old hash.
7. Every tick belongs to original consumers; rational allocated totals equal
   total ticks. Repeats, failures, edits, direct fallback and restart retain
   cumulative charges and the same original parent/deadline. USD and missing
   physical metering remain UNKNOWN, not zero.
8. Real canonical claim/fence and compare-and-swap publication are mandatory
   ports. Checkpoint, artifact and delivery precede acknowledgement. Stale
   workers and duplicate delivery cannot renew budgets or dispatch effects.
   Physical local harness interruption is not the real native worker proof.
9. Independent original-semantics checker must reject a changed output,
   omitted Work, forged binding, hidden stale source, fabricated checker result,
   altered shared projection and duplicated cost. Producer self-report never
   changes admission.
10. Mounted original Work must expose only its own projection and lifecycle,
    currentness, original resources and obligations. Missing mount is NOT_RUN.

## Frozen finite public sweep and stopping rule

The fixture builder preserves all 32 structural family names and indexes from
the sealed registration. Eight case obligations per family: two fresh useful
positive inputs, false candidate, out-of-profile alternative (no global
infeasibility claim), unauthorized input, currentness mutation, resource
exhaustion, and interruption/duplicate replay. Each family also exercises a
source insertion/retraction and an objective/programme edit. Fresh cases have
separate original data, source revisions and Work identities; lifecycle faults
are never counted as new structural families.

One finite 256-case development sweep, followed only by affected reruns after
verified fixes. The runner records every input, action, independent expected
output, actual disposition, error, source identity, checker identity and
replay path. It does not silently treat missing native integration or process
recovery as a passing local case. Three separate physical interruption
boundaries: after claim, after checkpoint/artifact, after delivery before ack.
No post-code unit tests. The E2E runner and original oracle are specified
before the producer; retained failures are immutable.

Positive estimator: independently accepted useful supported positives divided
by all offered supported positives, with UNKNOWN in the denominator. Require
≥95% and every critical falsifier rejected for the named finite development
scope. Missing real owner consumption/recovery means the full 32×8
qualification gate remains NOT_RUN, regardless of kernel results.
