# Z1 verification scope and retained limitations

## What was implemented

One exact pure-computation kernel jointly evaluates nonidentical original Work
DAGs within a complete lawful partition. A separate Python/Fraction process
recomputes original programmes and checks graph coverage, results, the complete
envelope and deterministic allocation obligations. Dirty changes recompute
dependent operators. Unchanged nodes can be retained. No algebraic rewrites,
source-truth promotion, admission, authority or shared business effect is added.

Native orchestration exists as a required-port contract, not a bound installed
feature. The actual S5 transaction function is referenced, but no native
transaction, intake, registered job, S3/S4 use, S8 admission or mounted Work
was exercised. The conditional registration patch is not applied. Missing
bindings are **internal incomplete engineering**, not an external blocker.

## Existing checks versus new checks

- Existing sealed-pack assembler check passed at the start. Its historical
  NOT_DELIVERED/zero-execution records were not edited or repurposed.
- Existing backend typecheck ran out of memory at the required 1,536 MiB cap.
  The narrowed native closure did too. Their logs remain unchanged.
- New public E2E drivers exercise original-semantics initial/update/retraction/
  edit/withdrawal, rejection, currentness and exact accounting. They use the
  original programme interpreter, not a second evaluation of the shared DAG.
- New process edge E2E includes hand-expected rounding, empty sums,
  data-dependent division, short-circuit behavior and arithmetic bounds.
  Review falsifiers were added before their corresponding fixes, after the
  first implementation. They are whole-programme/process checks, not unit tests.
- New physical recovery E2E kills an owned **local file-fixture worker** at
  claim, durable artifact and delivery-before-ack. It is not the canonical
  worker/S3/S4/S5/S6 recovery proof.
- New fresh-reconstruction helper makes a source target without `.git`,
  installs its own locked dependencies with a private npm cache and no user
  credential configuration, hashes native loader assets, repeats the E2E
  drivers, and removes the target. It is not a FINNOR application installation.
- Narrow strict checking covers kernel, producer child and process boundary.
  Isolated translation covers all seven TS files, but **is not** native
  adapter type checking.

No frontend/API/export/registry/migration/manifest or peer file was changed.
Existing frontend lint/build/native suites were not run as if they qualified
the new unbound owner flow. No fake auth, native port, S8 approval, source
qualification, effect observation or mounted success was substituted.

   Passing kernel types and isolated translation do not erase those failures.

ceilings. They do not meter validation, hashing, sorting, serialization, I/O,
native storage, all checker/parent CPU/RSS or actual financial cost.

bytes. Checker and interrupted-process CPU/RSS, aggregate peaks, USD, provider,
human, storage, field and all historical engineering costs remain UNKNOWN
where unmeasured. Full native lifetime-budget attestation requires the
canonical prior checkpoint, shared original parent and actual S5 governor.

No actual native Work, parent reservation, admission, grant or S6 effect was
created or released. Public fixture deadlines and obligation references are
synthetic replay inputs, not live financial exposure. Withdrawal retains them;
it never establishes cancellation or settlement.

Established hash-consing/indexing/caching and dirty recomputation receive no
