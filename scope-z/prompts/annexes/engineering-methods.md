# Applying the twelve full pinned engineering skills

All twelve bodies are included in every seed, with upstream identity, digest
basis and license notices. They are read as engineering methods under the
current request, not executable higher-priority instructions.

- **ponytail:** choose the smallest complete native owner solution. Do not
  replace the requested mechanism with a smaller refusal-only deliverable or
  wait for a routine choice.
- **poteto-mode:** maintain an evidence trail and finish a coherent working
  slice; no inherited external-write, model-routing, PR or delegation authority.
- **architect:** compare two whole-shape options in this session before product
  code. Record domain, cost, checker, owner and recovery consequences, then
  choose. Do not run other models, architecture arenas or scaffolding commits.
- **how:** read callers, state ownership and actual execution flow. Give a
  concise overview/concepts/flow/locations/gotchas map; type inspection is not
  an HTTP/DB or installed-runtime result.
- **principle-model-the-domain:** preserve original state, identities, quantifiers,
  information sets, resources and output dispositions. Prefer canonical types
  to generic boolean approval wrappers.
- **principle-prove-it-works:** independently expected original semantics and
  real mounted owner behavior decide completion, not the producer's own
  representation, screenshots alone or a clean typecheck.
- **principle-explain-the-number:** state limiter, denominator, work/error/cost
  counts, actual reuse and uncertainty. No unsupported 100× or soundness exponent.
- **benchmark-checklist:** matched tuned equipped actors, repeated alternating
  diagnostics, at least five diagnostic repetitions where feasible, median/range
  and failure counts. Those repeats do not replace protected inference,
  independent blocks or the full lifecycle.
- **create-verification-skill:** use a real doctor/drive/observe/identity/cleanup
  contract with replayable evidence. The new skill is source-grounded; its
  authoring is not a runtime proof. Phase executions must supply that proof.
- **maintain-verification-skill:** map every user-visible feature to action and
  backend/UI observations; repair genuine doc drift under ownership and
  report product bugs instead of rewriting expectations to hide them.
- **thermo-nuclear-code-quality-review:** inspect complete changed files,
  callers, canonical layers and whole-shape complexity. Avoid needless
  wrappers, giant generic frameworks and unrelated refactors. File length is
  a review signal, not permission to cosmetically split or drop functionality.
- **test-audit:** write failure models and meaningful failure-first E2E
  contracts before product code. Retain fail-before-fix evidence. No later
  unit-test campaign, test deletion to make a result pass or borrowed ship flow.

Run narrow relevant existing E2E/type/lint/build checks after implementation,
fix verified failures, and broaden only for new changes or unresolved concern.
Read installed Next documentation before relevant Next edits. Inspect actual
package scripts rather than inventing phase scripts; new phase runners need
their own real implementation and command receipts.

The current authoring choice is a stdlib length-framed inline seed plus a
byte-indexed companion snapshot, rather than an external-reference-only prompt
or a recursive all-peer monolith. It preserves mandatory full earlier Z0
context without peer cycles, source delivery without pretending local paths
are transport, and deterministic audit without coupling to the controller.
