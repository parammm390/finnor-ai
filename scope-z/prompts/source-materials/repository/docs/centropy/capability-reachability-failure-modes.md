# Capability reachability audit boundaries

Before extending the product path, verify these failures:

- A proxy allowlist entry is mistaken for a usable frontend control.
- A generated form silently skips a route whose actual request schema is absent from OpenAPI.
- A planner capability marked human-only is left without a governed human initiation path.
- An owner-only canonical operation is presented as available to every signed-in employee.
- An API acknowledgement is labeled verified without independent canonical readback.
- A compatibility workspace configuration recreates the retired primary four-surface navigation.
- An evidence-bearing reconciliation accepts an empty explanation or treats a human attestation as provider evidence.
- Browser push credentials are shown as ordinary manually entered business fields.
- A test file that merely mentions a capability is mistaken for a certified end-to-end journey.
- Human closing controls must reject service principals, an inactive/foreign employee, foreign canonical references, a forged verifier identity, changed payload under the same intake key, and malformed or unsupported action types. They must never ask the model to author the human decision.
- The effect compiler must preserve the grounded verifier as an employee PartyRef. Emitting employee as a canonical entity passes snapshot lookup but fails the database scope boundary; dropping the verifier would remove the exact approval basis.
- Human intake retries must preserve the one canonical Work/action/Thread and must not repeat a provider or domain mutation. Drafting requires a subsequent exact-effect review even if a tenant policy normally allows automatic execution.
- The frontend proxy must preserve an upstream Retry-After boundary and validated DELETE bodies. A dropped retry header prevents the operator from observing the actual retry window; a dropped body changes the exact reviewed request.

The final machine-readable report separates registered paths, source references, exercised browser evidence and externally blocked provider paths. Compatibility-only endpoints retain their backend owners and are classified explicitly.

Workflow recovery must read actual run/step identities and versions, preserve completed-step evidence, reject a stale version, redrive only a known failure before an effect, and produce a canonical control receipt. A controlled fixture cannot claim provider verification or completed business Work. Starting an Outcome Pack must retain one Work/Thread/input and the declared shadow/approval mode across reload and exact replay.

The final audit found that registering an Artifact API in the proxy did not expose blank draft creation, exact-version template registration, binding/lineage recording, spreadsheet cell editing or delegated recalculation. These need contextual human controls with immutable version/anchor review, canonical readback, unchanged base bytes, and no frontend formula evaluator. A stale patch must fail; unavailable Microsoft calculation must remain unavailable. A mission catalog that shows a disabled pack also needs the existing owner-only enable/disable control and a readback of the exact setting.

Supporting read controls must expose only explicitly registered GET routes, encode exact identifiers, collect the actual required query fields, show backend errors, and disclose bounded structured rendering. A route family name alone cannot establish a frontend path. Native authenticated SSE and alternate canonical intake routes need their own explicit audit treatment.

During the exact demo continuation, PostgreSQL recorded a real deadlock: plan insertion held the Work/plan transaction while waiting for the ObjectiveLoop foreign-key KEY SHARE; specialist finalization held FOR UPDATE on that same immutable ObjectiveLoop and waited for the plan transaction. Non-key state locks must continue to serialize state writers while permitting those foreign-key checks. A wrapped SQL error also exceeded the planner failure JSON limit, and the embedded plan's word "deadline" incorrectly classified it as a timeout. Persist a bounded actual cause and SQLSTATE rather than the entire SQL/parameter payload.
