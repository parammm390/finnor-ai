# S6 — Governed execution

Frozen responsibility: discharge authorized real-world obligations with accountable
settlement. Canonical primitive: DurableObligation. The eight scopes, five contracts,
and architecture lock remain unchanged. Current working source, rather than historical
main, is the implementation baseline; exact identities are in start-manifest.json.

The full frozen gate remains required. Local qualification is evidence toward it,
never a replacement gate. No economic multiplier or frontier dominance follows from
operational reliability. No production keys, release approval, provider guarantees,
or protected admission are inferred or self-issued.

## Domain and failure model registered before implementation

Existing canonical BusinessEffects, workflow attempts/fences, physical provider
invocations, observations, and allocation commitments are retained. An obligation
binds these owners; it does not create a competing effect or resource ledger.
Initial supported mechanical IR will be exact typed target-field replacement with
explicit account, unit, null/clear semantics, version precondition and independently
qualified readback. Other requests require an explicitly verified adapter contract.
Generic browser WRITE, unrestricted shell/SDK/HTTP, shared credentials and mutable
capability flags cannot supply protected admission. Their absence remains a full-gate
limitation; a blocked unsafe path is not executor conformance evidence.

Threats include malicious producers/executors, forged identity/reference/receipt,
cross-tenant access, request substitution, stale authority, evaluator-secret access,
credential/network/filesystem/child escape, corrupt or rolled-back ordinary storage,
duplicate/reordered delivery, provider acceptance with lost response, expired
idempotency protection, stale leases and deployment changes. Protected runtime/OS,
cryptography, independently provisioned identity/key material, immutable reviewed
release identity and monotonic protected commitments are inherited dependencies.
Same-process trusted-plugin checks remain explicitly bounded engineering protection.

Failure model: durable intent precedes possible egress; possible delivery is never
erased on cancellation, expiry, stale worker or crash. Provider acceptance is distinct
from observed/verified settlement. Unsupported readback retains uncertainty. Retry
requires payload-bound provider protection within its real lifetime, or qualified
no-effect reconciliation. Parent/member completion requires every required member.
Compensation has a separately authorized linked identity.

Initial structural budgets: 2 MiB input, 8 MiB record, 256 live obligations/tenant,
64 members, 16 resources, 30 seconds admission, 64 attempts/obligation, explicit
deadline/lease and human/compute/resource envelopes. These are initial implementation
bounds, not measured production guarantees; refine only before the affected scored
run with an appended registration. External costs remain unknown if unmetered.
No paid resources or consequential production targets are authorized by local tests.

## Test selection and audit discipline

Apply the complete retained OpenClaw test-audit skill at
`finnor-research/references/openclaw-test-audit/SKILL.md`. Each workstream records
the observable contract, credible regression, missing coverage and test-only seam
assessment before authoring. Extend the strongest existing owner boundary when it
already owns a failure. New capability absence is not a demonstrated bug regression.
Regressions must fail before repair for the intended reason. No tests are deleted.
No relevant source/test edits occur during a shared Vitest run. FINNOR installed
Vitest/tsx and disposable EmbeddedPostgres replace unavailable OpenClaw runners;
Solo adversarial review and executable challenges replace unavailable autoreview;
independent human review remains a completion/release dependency. The user explicitly
prohibits subagents.
End-to-end runs retain exact inputs, source/runtime versions, requests/readbacks,
faults/transitions, receipts, unresolved liabilities, accounting and rerun commands.

## Initial classification

KEEP: effect identity, native attempt/provider invocation/unknown machinery,
immutable upstream owners and allocation reservations, artifact conditional updates.
BROKEN: page-wide/null browser verification, model act bypass, producer-declared
verification, stale gap between plugin preflight and individual tool dispatch.
BOUNDED: same-process trusted plugins, header development identity, ordinary RLS
and SQL immutability, local provider fixtures. MISSING: canonical obligation joins,
protected append/egress/admission, hostile worker confinement and allocation-bound
settlement integration. COMMODITY: PostgreSQL, Node/crypto, existing workflows,
browser/provider machinery and OS isolation. REPLACE: unsound completion predicates
and unprotected claims of admission, while preserving historical evidence.
