# Execution-pack sealing failure model, before its builder

This is local document/receipt packaging, not a remote launcher or product
runtime. Preserve the product lock, historical failures and unreceived context.

Credible failures:

1. Seal a transient authoring output rather than the reviewed final index and
   receipt. Pin both actual reviewed digests and verify every indexed byte.
2. Omit one of six complete seeds, a required full Z0 dependency, a full supplied
   text, skill, license or companion. Run the actual assembler's complete check
   before sealing; inventory the complete index, not just six prompt paths.
3. Accept a different product lock, source commit/tree or changed original member.
   Reuse the controller's fixed trust anchor and the assembler's source checks.
4. Put a manifest's own digest inside its members. Keep the final seal receipt
   outside the manifest and do not embed that digest in role-seed members.
5. A cold coordinator or prompt engineer executes the embedded Z0 assignment.
   Frame the whole Z0 seed as reference and put a complete own-role directive
   after it; include all six concrete phase bodies.
6. Missing/ambiguous Computer, model, transfer or read facts become invented
   launch success. Keep NOT_DELIVERED/NONE_OBSERVED and explicit actual dates.
   Local model-settings observations are not remote Computer attestations.
7. A source probe or clean dependency install becomes installed owner/runtime
   proof. Preserve exact narrower evidence classes and unfinished gates.
8. Unrecognized outputs or symlinks are overwritten. Use no-follow bounded
   reads and descriptor-relative exclusive creation; same bytes are idempotent,
   different bytes stop without replacement. Retain partial failed publication.
9. A credential/private file enters the bundle through a broad filesystem scan.
   Use the already checked index plus an explicit coordinator-owned allowlist;
   never enumerate .env, credential stores, node_modules or raw session history.
10. Rebuilding changes seed/manifest bytes. Derive output only from immutable
    input bytes and fixed metadata, never a new timestamp or live API call.
11. Execution-pack validity is mistaken for the required three running phases,
    qualified advances or 100×. The builder may only prepare or verify files.
12. New D1 facts are lost. Both role seeds carry the complete native-query
    clarification; actual phase launch must carry that same file in a new
    immutable current-source snapshot.

Finite verification: retain a real controller CLI failure while the pack is
absent, then run the reviewed prompt assembler and build twice identically,
build the role/seal outputs, check exact rebuilt bytes, and run the actual
controller verifier on the complete non-fixture pack. The existing 37-case
subprocess E2E covers member mutation/missing/simulation/launch-state behavior.
Neither those SIMULATED cases nor the real local manifest check show remote
delivery or FINNOR business behavior. No post-code unit tests will be added.
