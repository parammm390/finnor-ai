# Cold context reconstruction: pre-code failure model

This is an offline context/control reconstruction, not a product installation.
The sealed first pack is immutable; new reconstruction evidence is external.

1. A fresh pinned source checkout lacks an untracked preimage present on the
   coordinator, especially the historical draft checked by verify_product.
2. A local object alternate, node_modules symlink or copied environment makes
   a supposedly cold reconstruction secretly depend on the original target.
3. Archive traversal, symlink/hardlink entries or overwrite destroys other work.
4. Original source/lock, canonical skill, full companions or original failure
   bytes are absent even though a six-seed hash check passes.
5. A failed check adds evidence inside its indexed context; “repairing” that
   failed target silently changes validation inputs or erases the failure.
6. A bootstrap companion supplies an altered historical goal or extra files
   not bound to the reviewed index's exact historical preimage.
7. A source-only reconstruction is called installed FINNOR or real delivery.

Finite E2E: create an independently copied Git checkout at the original source
base with no dependencies/environment files; extract the exact sealed archive
without clobber; run the real assembler, builder and controller CLI. Retain a
first missing-preimage failure unchanged. Then use a new fresh target with a
separately hash-bound one-file bootstrap companion and repeat every CLI.
Never reuse/delete the failed target or rewrite either original lock.
