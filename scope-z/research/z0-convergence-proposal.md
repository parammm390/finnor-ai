# Z0 convergence scope, proposed for the common PRD

Status: coordinator proposal, NOT LOCKED. No product source has been changed.
Source cut: `7bfdd2d3ab611c90f1355637858824ff1ba67f98`.

## One outcome and output

Deliver one **ConvergedInstitutionRuntime**: the installed existing FINNOR runtime in which an authorized ordinary Work can discover, request, observe and consume the eligible admitted computational capabilities through their real owners, without manual transcript stitching or a parallel orchestrator.

This is a release/runtime identity and conformance contract, not another canonical business state, grant ledger, admission receipt, or scientific invention. Its principal output is the integrated product, not a capability JSON file or report.

Z0 restores the full intended X/Y composition and systemic product access where code already supplies the underlying capability. It supplies no Z1–Z5 novelty credit. Equivalent Z0 adapters/fixes are available to every comparison actor. It does not complete unrelated Y publication, deployment or certification.

## Finite development acceptance before repair

Write the failure model and independent inputs/expected observations before production changes. Preserve at least:
- D1 valid harness/confidential requests reaching their real readers and the economic positive control; malformed identities, wrong Work, revoked/cross-tenant principal and unrelated extra-envelope fields fail correctly.
- D2 deliberate omitted-entry and missing-context mutations fail a canonical completeness check; wait/check/native-only/human-only classifications remain distinct.
- A real X1-origin responsibility requesting X2 with original parent/remaining grant/deadline, checker acceptance and actual owner consumption; new-work budget reset fails.
- At least one other existing native scientific family selected from ordinary Work reaches its actual consumer. Choose using measured accessibility gaps; do not add a ceremonial generic tool for already reachable code.
- A supported opaque/UNKNOWN effect survives loss of response, physical worker interruption, duplicate delivery and reconciliation under the same obligation identity. No new real-world effect is authorized.
- Currentness/revocation races at claim, acceptance and use; unrelated valid work continues.
- Mounted reload, Work/root/principal switch, token refresh, true logout/new sign-in, offline/reconnect, revocation and delayed old-principal responses cannot resurrect private data or turn a candidate into a verified result.
- Final emitted API/worker and affected mounted path run from a separately installed, lock-restored reconstruction; source-only probes remain separately labeled.

Each case retains exact source/build/schema/job/Work identity, original inputs, independent oracle, observed API/SQL/queue/process/owner/browser state, failures, exit/cleanup, costs/gaps and repeatable command. Run installed stacks serially on the present 8 GiB host unless concurrency itself is the registered bounded case. Do not borrow original-checkout dependencies and call that clean reconstruction.

## Falsifiers

Z0 fails software completion if eligible supported capabilities remain inaccessible through their intended product flow, native effects become unconstrained model tools, the runtime invents success from transport, original budgets/UNKNOWN are lost, private results cross principals, the canonical catalogue can silently omit capabilities, or the promised installed positive path remains unrun.

A correct visible unavailable capability is not a false defect. Protected qualification/production/financial claims remain separate from source repair and development E2E. Missing internal adapters, checker, packaging, meters or Work integration remain incomplete engineering, not external blockers.
