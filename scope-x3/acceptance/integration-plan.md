# Installed-boundary verification, preregistration

This addendum freezes integration predicates before the corresponding host code.
It does not modify the independent v1 cases, their digest, or their custody.
The A–J names in the independent manifest remain provisional, not quotations from
an unavailable document.

## Commands and artifacts

Run `PATH=/home/factory-user/x3-tools/node_modules/node/bin:$PATH npm run typecheck`
from `finnor-os`. Run
`FINNOR_X3_EVIDENCE_DIR=<absolute-private-directory> node --import=tsx scripts/x3/run-installed.mts`
there for the actual installed proof. The driver must retain selected inputs,
literal expectations, observations, queue/delivery identities, ordinary-role SQL
readback, source hashes, process start/stop, counters, and failed attempts.
Tokens, signing keys and connection credentials must not enter artifacts.

## Predicates and failure families

1. Authenticated intake commits a canonical Work, immutable specification and
   durable versioned job before reporting acceptance. Network replay returns the
   same identity; a changed body under that key conflicts. Foreign tenants see no
   application, record, asset or history.
2. A separate physical worker consumes that job under ordinary worker authority.
   Its source/runtime/schema cut and its delivery token/fence are checked again
   before staging and publication. An expired or replaced delivery cannot publish.
3. Compiler output is data, not guest code. The installed program is the output
   that actually makes decisions. A separate specification interpreter compares
   named acceptance vectors against it. A mutated instruction or omitted action
   is a negative control, never a successful release.
4. Generated forms cover every declared entity, field, state and action. Browser
   and HTTP actions use the same authenticated operations. Refresh preserves
   actual data. Untrusted labels render as text. No builder token, role assignment,
   arbitrary URL, HTML, script, SQL or process capability enters the product.
5. Exact quantities retain dimensions and decimal strings. Exercise the frozen
   integer-over-2^53, one-minor-unit mismatch, inclusive threshold, USD/INR/EUR,
   UNKNOWN/conflicting evidence and stale-source cases. If a stricter typed
   boundary refuses invalid creation before the model's reconcile operation,
   report that boundary difference separately; do not invent a stored DRAFT or
   label the frozen literal case an installed pass.
6. Roles come from active canonical employee assignments and current scoped
   authority, not request fields. Distinct approvals bind the immutable release,
   semantic record revision, exact values and source pins. Recheck all approvers
   at preparation, including expiry, suspension and explicit deny.
7. Concurrent writes use expected revision and serialize on the actual record.
   One competing edit succeeds and the other conflicts; idempotent retry must
   not duplicate history, approvals, proposed effects or usage. Run 16 clients.
8. All three maintenance classes run through the same durable build/install path:
   business/unit changes, identity/concurrency changes, and schema/dependency/
   deployment changes. Old record quantities, creation contracts, decision
   history and source pins remain readable. Existing records require explicit
   rebase/edit before decisions under a changed release.
9. Installation validates every actual record and all declared migration steps
   in one transaction. Illegal loss, removed fields or incompatible states refuse
   without changing the installed head or data. Record before/after digests.
   Interrupt after staging, replace the worker, and complete the original build
   without resetting its deadline or grant.
10. Rollback checks actual data and outstanding canonical obligations. Safe
    rollback retains history. Unsafe rollback blocks and allows explicit forward
    repair. Cancellation fences queued/in-flight publication and later actions
    without deleting data, history, cost or effects.
11. A prepared application action is not an execution. Any consequential adapter
    must obtain real S4 preparation, S5 consumption and S6 obligation references,
    verify exact application binding, and never manufacture evidence. Ordinary
    development signing/dispatch fixtures are not protected or live authority.
12. P7 impact closure includes business/specification, source, identity, schema,
    checker, runtime, assets and installed head. Typed S8 evaluation/promotion/
    consumption/revocation preserves evaluator/promoter separation and existing
    domains. Development success does not enable production.
13. Enforce the original deadline and cumulative build/release/mutation/storage/
    output limits. Retry and restart consume the same allocation. Hold a second
    build behind the existing compute governor. Refuse oversize and unsupported
    inputs without truncation. Report unknown aggregate memory/money/human meters.
14. A second, independently specified record/state graph must install and operate
    without changing compiler, runtime, service or UI source. Maintenance episodes
    change declarations, not application-specific backend code.
15. Replay all historical migrations, upgrade the retained prefix, replay again,
    preserve a pre-existing job, and compare generated migration/OpenAPI/authz
    artifacts. Build the actual API and mounted frontend and run final emitted
    worker imports. Missing Docker/ARM64 evidence stays explicitly unverified.

The separate 20-application/60-maintenance protected qualification, production,
operational 100× and financial gates remain unchanged and NOT_RUN. No model-only,
development, source-run or unavailable-comparator result substitutes for them.
