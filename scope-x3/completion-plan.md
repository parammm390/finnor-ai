## Two delivery designs

1. Mutate the stored release package on installation, cancellation, admission,
   and every effect. This mixes immutable content identity with changing owner
   state, would require migration/backfill, and risks rewriting old evidence.
2. Keep immutable release bodies and expose the complete common envelope as an
   authenticated projection of existing canonical records and event streams.
   Its content digest names the immutable release body, not its own recursively
   hashed metadata. History and costs remain references, not copied ledgers.

Choose the second design. The shared package types describe the stored release
binding separately from the delivered package. The existing application read
consumer assembles the envelope in its already-authorized transaction. Existing
Work renders that package through its current evidence section.

## Complete envelope acceptance

The installed package must contain `envelope` with every following logical
field. Names below are the acceptance contract, not inferred candidate output.

```
artifact_id kind schema_revision content_digest
tenant_ref work_ref institutional_program_ref
parent_artifact_refs producer_revision baseline_manifest_ref
authority_grant_ref rights_revision resource_grant_ref
source_refs source_revision_vector knowledge_cut
admitted_domain_ref application_fingerprints
model_refs dependency_lock_digest runtime_digest
observed_claims inferred_claims predicted_claims unresolved_claims
postcondition_contract_refs independent_check_refs
S6_obligation_refs provider_observation_refs
invalidation_dependencies lifecycle_state lifecycle_events
build_learning_compute_cost_refs attributable_human_work_refs
```

Independent installed expectations:

* Artifact, tenant, Work/input, application, specification, producer, checker,
  source, lock, schema, installed release, and original allocation match the
  actual SQL rows and frozen input. A client cannot supply an envelope.
* `content_digest` equals an independently recomputed SHA-256 over the canonical
  immutable release body. The digest basis is explicit. Adding a current-state
  projection must not rewrite that body or any old release.
* Source references retain every original host source digest. The supported
  profile is development, not an invented admitted domain or qualified B_V.
* Independently checked properties name the actual stored checker result and
  its bounded scope. An installation event is evidence of installation, not
  truth of every business assertion or protected whole-product verification.
* Lifecycle, S6 responsibility, and cost collections name the existing
  application-history operation, the authorized application, exact event kinds,
  actual count, and a bounded snapshot cursor. They do not silently truncate
  events or create a competing effect, success, or cost ledger.
* S6 obligation references resolve to actual `S6_BOUND` records. A zero count
  comes from SQL, not a default. Preparation does not become provider
  observation, execution, settlement, or production authority.
* Missing institutional-program, immutable authority-grant, independent
  admission, provider-observation, aggregate cost, and human-work evidence is
  explicitly `UNKNOWN` with a reason. An absent learned model is explicitly
  not used, not a guessed provider or zero-priced invocation.
* Unchanged reads produce the same envelope. Revocation, foreign tenants,
  cancellation, failed maintenance, and retained historical releases keep their
  real owner dispositions. The projection grants no new access or authority.

Failure families are missing fields; fabricated references or empty costs;
self-referential/wrong-body digests; copied success/effect ledgers; leaking
foreign data; truncating history; treating STAGED metadata as installed truth;
optimistic admission; stale-source/session reuse; and poll-time identity churn.

The primary proof extends the existing installed HTTP/queue/SQL campaign.
Expectations use literal field names and an independent canonical JSON encoder,
not the package constructor or its digest helper. The actual effect campaign
must resolve the S6 collection after genuine owner preparation. Existing
browser evidence must be rerun because the runtime source digest changes.
No post-code unit tests are added.

2. Install both existing lockfiles, without changing either.
